## 폴더 구조

```text
AGENTS.md                 # 작업 규칙 진입점
CLAUDE.md                 # AGENTS.md 불러오기
CODEX.md                  # 보조 안내
docs/PROJECT-RULES.md      # 공통 제약 배포용 복사본
contracts/README.md       # 계약 원본·버전·사용 범위
src/
  pages/                  # 로그인·시민·담당자·관리자 화면
  components/             # 공통 입력·목록·오류·로딩 표시
  api/                    # Flask API 호출과 오류 처리
  styles/                 # 공통 스타일
tests/                    # 화면·실제 API 연동 검증
```

빈 폴더의 `.gitkeep`은 첫 실제 파일을 추가할 때 제거할 수 있다. 프론트 기술 확정 후 진입 파일·빌드 설정·정적 자산 위치를 추가한다. 기술 선택 전에 React 등 특정 프레임워크의 명령을 가정하지 않는다.

## 최초 연결·인수

1. 백엔드와 같은 계약 커밋으로 로그인·세션·민원 API를 맞춘다.
2. 계약의 합성 예시로 화면을 만들 때는 개발용 모드임을 표시한다.
3. 실제 백엔드에서 로그인·민원 저장·새로고침 후 조회·담당자 처리·시민 상태 갱신을 확인한다.
4. 인증 만료·타인 민원 접근 거부·실패·빈 목록·키보드 조작·좁은 화면을 확인한다.
5. 배포 시 프론트와 백엔드의 커밋을 함께 기록하고 정적 파일 배포 경로를 FIM 담당에게 전달한다.

보안 대시보드는 관제 PC의 별도 서비스다. 관리자 링크 주소는 합의된 설정값으로 제공하고 시민 화면에는 노출하지 않는다. 링크 숨김과 별도로 관제 서비스 자체에서 접근 권한을 검사해야 한다.
