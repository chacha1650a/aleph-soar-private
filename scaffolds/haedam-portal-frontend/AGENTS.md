# 해담시청 프론트 작업 규칙

## 먼저 읽기

이 파일 → [공통 제약 복사본](docs/PROJECT-RULES.md) → [README](README.md) → 담당 작업 카드 → 해당 API 계약 순서로 필요한 내용을 읽는다. 사용자 명시 지시를 우선한다. 공통 제약의 원본은 capstone에 있으며 변경 시 양쪽 저장소에 같은 버전을 반영한다.

## 현재 상태와 경계

- 이 저장소는 해담시청 민원포털의 화면 담당이다. 현재는 문서와 빈 폴더만 있으며 앱·의존성·실행 명령은 없다.
- 2026-10-19 사용자가 React + Flask를 선택했다. 이 폴더는 과거 복사용 스켈레톤이며 실제 구현·버전·잠금·실행 명령은 haedam-portal-frontend 저장소의 README를 따른다.
- 기본 수정 영역은 `src/pages/`, `src/components/`, `src/api/`, `src/styles/`, 관련 `tests/`다. 공통 빌드 설정·계약 복사본은 담당을 조율한다.
- 시민 로그인·민원 작성·본인 조회, 담당자 처리, 관리자 계정 관리 화면을 단계적으로 구현한다. 화면별 실제 권한은 계약에서 확인하며 서버가 검사한다.
- 보안 대시보드와 티켓 시스템은 관제 PC에 둔다. 관리자 메뉴 링크만 제공하고 관제 화면을 이 저장소에 중복 구현하지 않는다.

## 구현 제약

- API 호출은 `src/api/`로 모은다. 주소·타임아웃·인증 만료·계약 오류를 일관되게 처리한다. 비밀키·DB 연결·n8n 관리 자격 증명은 프론트에 넣지 않는다.
- 로그인 상태나 역할을 임의의 로컬 값으로 만들어 실제 권한처럼 쓰지 않는다. 개발용 합성 모드는 명시하고 실제 연결 실패를 가리지 않는다.
- 민원 본문 등 사용자 입력은 안전하게 출력한다. 인증 정보·개인정보를 브라우저 저장소·콘솔·오류 추적에 남기지 않는다.
- 상태 변경 성공은 서버 결과로 확인한다. 로딩·빈 값·입력 오류·인증 만료·권한 거부·API 실패·재시도를 구분한다.
- 키보드 조작·입력 레이블·오류 안내·좁은 화면을 확인한다. 관제 구현 세부 정보를 시민용 업무 화면에 넣지 않는다.
- 실제 정적 배포 경로와 정상 빌드 변경을 C의 Wazuh FIM 담당에게 전달한다. 소스 폴더와 실서비스 배포 폴더를 혼동하지 않는다.
- 레포 분리가 별도 HTTP 프록시 도입을 뜻하지 않는다. 초기 실습 배포는 빌드 결과를 Flask 앱에서 함께 제공하는 안을 검증한다. 화면 라우트·정적 파일·API·없는 경로를 구분하고 미지정 경로의 404와 `web-scan` 신호를 보존한다.

## 계약과 확인

- `contracts/README.md`에서 계약 원본 커밋을 확인한다. 계약 변경은 capstone 원본과 백엔드 소비자까지 함께 조율한다.
- 최초 인수는 실제 Flask 백엔드로 로그인 → 민원 작성 → 새로고침 후 조회 → 담당자 처리 → 시민 상태 확인이다. 화면 샘플만으로 통합 완료 처리하지 않는다.
- 도구가 추가되면 실제 빌드·관련 검증과 브라우저 확인을 수행한다. 현재 존재하지 않는 명령을 실행 가능하다고 보고하지 않는다.
- PR에 변경 화면·계약 커밋·백엔드 커밋·실행 결과·화면 확인·미연결 항목을 적는다. 작업 브랜치·리뷰·민감 데이터 규칙은 공통 제약을 따른다.
