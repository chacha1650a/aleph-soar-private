# 해담시청 백엔드 작업 규칙

## 먼저 읽기

이 파일 → [공통 제약 복사본](docs/PROJECT-RULES.md) → [README](README.md) → 담당 작업 카드 → 해당 API·이벤트 계약 순서로 필요한 내용을 읽는다. 사용자 명시 지시를 우선한다. 공통 제약의 원본은 capstone에 있으며 변경 시 양쪽 저장소에 같은 버전을 반영한다.

## 현재 상태와 경계

- Flask 기반 해담시청 민원 API를 구현할 저장소다. 현재는 문서와 빈 폴더만 있으며 실행 가능한 앱·의존성·DB는 없다.
- 기본 수정 영역은 `src/haedam_portal/`, 관련 `tests/`와 합의한 DB·마이그레이션 설정이다. Python·Flask 버전·의존성 잠금·환경 준비 명령은 초기화 작업에서 실제 확인 후 README에 적는다.
- `auth/`: 인증·세션·역할. `petitions/`: 민원 생성·조회·상태 전이. `admin/`: 승인된 계정 관리. `integration/`: 구조화 이벤트·허용된 대응·원복 연결.
- Graylog·Wazuh·Suricata 탐지, pfSense·VPN 제어, n8n 워크플로, 관제 대시보드·티켓 서비스는 해당 담당과 연결한다. 포털 내부에 중복 구현하지 않는다.
- 기획서는 MySQL을 계획한다. 로컬 대체 DB가 필요하면 차이·사용 목적·검증 한계를 기록하고 MySQL 연결 완료로 보고하지 않는다.

## 구현 제약

- 앱 생성과 환경 설정을 분리하고 테스트 환경은 격리한다. 실제 DB·로그·비밀값·세션 키를 커밋하지 않는다.
- 모든 API에서 인증·역할·객체 소유권과 담당 범위를 서버가 검사한다. 프론트가 보낸 사용자·역할을 신뢰하지 않는다.
- 입력 검증·상태 전이·트랜잭션·오류 응답을 계약에 맞춘다. 비밀번호 해시, 세션 만료·로그아웃·회수, 선택한 인증 방식의 CSRF 방어를 구현한다.
- 브라우저 업무 API와 n8n 대응 API의 권한을 구분한다. 관리망·호출자 인증·허용 대상·중복 처리·사전 상태·복구 수단을 검증한다.
- S1 IP 차단과 S4 계정 잠금을 혼용하지 않는다. S4는 기존 세션도 회수하고 비밀번호 재설정 뒤 해제한다. 차단·해제는 실제 대상 상태를 확인한다.
- 앱 IP 차단은 pfSense 차단과 별개다. 초기 배치는 HTTP 프록시 없이 연결 주소를 사용하고 `X-Forwarded-For`를 무시한다. 로그인·접근 로그·차단 검사는 공통 IP 해석 함수를 사용한다. 관리망·관제 호출자의 자기 차단을 막는다.
- 프론트 빌드 결과의 정적 파일 제공과 실제 404의 로그 발생을 함께 검증한다. 화면 라우트 처리가 `web-scan` 신호를 없애지 않아야 한다. 프록시를 추가하면 신뢰 경계·우회 차단·S1·S8·S10 검증을 먼저 갱신한다.
- S7 복구는 승인한 경로와 원본만 사용한다. 외부 입력으로 임의 파일 접근·셸 실행을 제공하지 않는다.
- 이벤트·로그·오류에 비밀번호·토큰·쿠키·민원 원문·실제 개인정보를 남기지 않는다. 합성 데이터와 실제 관측 결과를 구분한다.

## 계약과 확인

- `contracts/README.md`에서 원본 커밋을 확인한다. API·이벤트·사건 변경은 capstone 원본과 프론트·탐지 소비자를 함께 맞춘다. 기존 스키마로 표현할 수 없는 이벤트는 먼저 계약을 보완한다.
- 초기 구현 시 격리된 개발 환경 준비·테스트·실행·DB 초기화·마이그레이션·합성 데이터 정리 명령을 검증 후 README에 적는다. 없는 명령을 완료된 환경처럼 안내하지 않는다.
- 정상 로그인·잘못된 인증·무권한·타인 민원 접근·저장 후 재조회·재시작 후 데이터 유지를 확인한다. 대응 구현 후 재시도·실패·세션 회수·원복을 확인한다.
- 외부 연결 검증 전에는 이벤트 생성 성공과 SIEM 도착·탐지·대응 성공을 분리한다. 미구현 API를 성공 응답으로 채우지 않는다.
- PR에 계약·프론트 커밋, 실제 실행·검증 결과, DB 영향·복구 방법과 미연결 구간을 적는다. 작업 브랜치·리뷰 규칙은 공통 제약을 따른다.
