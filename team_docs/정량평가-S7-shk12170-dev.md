## 1. S7 측정 대상

| 항목 | 내용 |
| --- | --- |
| 공격 | 포털 웹 디렉터리(`FRONTEND_DIST`, 호스트 bind mount)의 파일 변경 또는 새 파일 생성 뒤 같은 경로 접근 |

| 원복 | 격리한 시험 파일 삭제, 원본 해시 확인 (기준본은 바꾸지 않음) |
| 출발지 | Kali `203.0.113.31~39` (C 대역) |

## 2. 검문소별 채점 (S7)

| 검문소 | 확인할 것 | 값의 출처 | 지표 |
| --- | --- | --- | --- |
| A 신호 도착 | FIM 경보와 파일 접근 이벤트가 Graylog에 도착 | Wazuh `alerts.json`, Graylog 검색 | 신호 도착률, 수집 지연(★) |
| B 판정 | S7 이벤트 1건, 정상 배포는 허용 표시로 제외 | Graylog 이벤트 | 탐지율, 오탐, MTTD |
| C 대응·효과 | 117 실행 결과 `ok`, 해시 일치·404, 정상 접근 유지 | `s7-restore.log`, 재요청 결과 | 자동 대응 성공률, 정상 업무 영향(★) |
| D 티켓 | 자산 + 파일 키로 티켓 1건, 복구 경보·404 확인으로 중복 없음 | 티켓 저장소, n8n 실행 기록 | 사건 묶기 정확도(★) |
| E 원복 | 격리 시험 파일 삭제 뒤 웹 루트 해시 = 해시 목록 | 해시 비교 출력 | 원복 성공률, MTTR, 원복 소요시간(★) |
| F 증적 | 실행별 원본 로그(Wazuh 경보 JSONL·포털 event_id·중계 통계), 파일 내용·비밀값 없음. 화면 캡처는 증적으로 쓰지 않음 | `docs/capstone/evidence/S07/` | 증적 완비율(★), 민감정보 노출(★) |

- MTTD = S7 이벤트 생성 시각 − **조건 충족 시각(나중 신호 = 같은 파일 키의 성공 접근)**. 첫 공격 시각(파일 변경)은 따로 기록한다.
- MTTR = 효과 확인 통과 시각 − 이벤트 생성 시각. 117 완료 시각도 따로 적는다.
- 보고 형식: 중앙값 ○초 · 최댓값 ○초 · 성공 ○/N · 미탐 ○ · 시간 초과 ○

## 3. 테스트셋 (S7, 11회)

S7은 결합 조건(FIM + 접근) 케이스라 "조건 일부만 충족"이 들어간다. 실행마다 **다른 시험 파일 경로**와 `run_id`를 쓴다(묶기 키가 파일 키라 같은 경로면 앞 실행 집계가 남음).

| # | 입력 | 보강 | 기대 | 분류 기준 |
| --- | --- | --- | --- | --- |
| 1 | 전체 조건 충족(새 파일 생성 → 10분 안 접근) | 전 | 공격 성공, 로그만 남음, 이벤트·티켓 없음 | 증적용 |
| 2~4 | 전체 조건 충족: 새 파일 생성 → 접근 | 후 | 발동 1 → 117 격리 → 404 → 티켓 1 | 탐지율·대응 |
| 5~6 | 전체 조건 충족: 기존 파일(`index.html` 등) 변경 → 접근 | 후 | 발동 1 → 117 복구 → 원본 응답·해시 일치 | 탐지율·대응 |
| 7 | 조건 일부: 파일 변경만, 접근 없음 | 후 | 미발동 | 경계 오탐 |
| 8 | 조건 일부: 접근만, 변경 없음 | 후 | 미발동 | 경계 오탐 |
| 9 | 시간 창 밖: 변경 뒤 10분 넘겨 접근 | 후 | 미발동 | 경계 오탐 |
| 10 | 혼합: 파일 A 변경, 파일 B 접근 | 후 | 파일별 판정, 미발동 | 묶기 정확도 |
| 11 | 정상 업무 30분: 정상 화면 접근 + 배포 스크립트로 정상 배포 1회 | 후 | 이벤트 0, 정상 요청 성공 | 정상 업무 오탐·영향 |

- 2~6에서 6단계 중복 확인: 복구 뒤 FIM 재경보(복구본 해시는 해시 목록에 있음)와 404 확인 요청으로 S7이 다시 발동하지 않아야 한다.
- 보강 전/후 조건: 전 = 수집은 연결, S7 규칙·117 없음, 컨테이너 웹 디렉터리 쓰기 가능. 후 = S7 규칙·117, 코드 디렉터리 읽기 전용 마운트(제안). 바꾼 항목은 변경 목록에 하나씩 적는다.
- 순서 반대(접근 404 뒤 생성)는 순서 조건을 두지 않기로 해서(제출본) 측정하지 않는다.
