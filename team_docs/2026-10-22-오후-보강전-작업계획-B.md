## 2. 첫 공동 작업 · 포털 GELF 실수신

1. **D:** 10.250.0.100:12201/UDP, `haedam GELF UDP` 입력·호스트 게시·Windows 수신 방화벽·스트림 상태 확인. 다른 PC에서 들어오는 실제 포털 로그를 확인할 준비를 한다.
2. **B:** 현재 A .2→D .100 UDP 12201 허용·반환/연결 상태를 확인한다. B가 오전 적용한 규칙을 중복 추가하지 않는다.
3. **A:** 실제 systemd 서비스가 읽는 환경 파일에 GELF_ENABLED=1·D 주소·포트를 반영하고 `systemctl restart haedam-portal`을 수행한다. 환경 파일 수정만으로 실행 프로세스 값이 바뀌었다고 가정하지 않는다. 비밀번호·환경 파일 원문을 공유하지 않는다.
4. **A 준비 완료 후 B:** 실제 Kali .10에서 공개 URL `http://203.0.113.1/login` GET **1회**를 보내고 KST 요청 구간·HTTP 코드를 제공한다. 접속 준비용 GET은 보강 전 공격 횟수로 세지 않는다.
5. **A·D:** A의 실제 JSONL event_id와 D의 같은 event_id·event_type·asset_id·src_ip·경로·상태를 대조한다. HTTP 200만으로 GELF 성공을 판정하지 않는다.
6. **S7 시작 전 추가 확인:** A→D 실제 `web.file_access`가 오는지 확인한다. GET의 `web.request`만 검색된 것으로 파일 접근 로그까지 완료 처리하지 않는다. 실제 시험 파일과 같은 asset_id/file_key를 연결할 수 있어야 한다.

UDP는 송신 오류가 없어도 유실될 수 있다. 별도 기록에 큰 UDP 단편 유실·C TCP 중계 전환 보고가 있으므로 작은 표식 1건만으로 모든 실제 메시지 크기의 전달을 보장하지 않는다. 필요한 원본이 D에 도착하지 않으면 보강 전 성공으로 세지 않고 수집 문제로 분리한다.

## 3. 보강 전의 뜻과 시작 조건

**로그 수집은 연결·유지하고, 해당 케이스의 팀 추가 상관·자동 대응·복구는 없거나 꺼 둔다.** Wazuh 기본 FIM 경보·Suricata 원본 경보·pfSense 원본 로그는 수집 증거다. 기대하는 “안 울림”은 **해당 케이스 상관 이벤트 없음·자동 대응 없음·티켓 없음**이며 모든 원본 경보가 0건이라는 뜻이 아니다.

시작 직전에 담당별로 확인한다.

- 케이스의 필수 원본 신호가 D Graylog 검색에 보인다.
- Graylog Event Definitions에 해당 케이스 규칙이 없거나 Disabled다. 수업 규칙이 같은 입력에 반응하는지도 확인해 격리·상태를 기록한다.
- 해당 n8n 자동 대응·복구 워크플로는 없거나 Inactive다. 수신/기록용 보조 워크플로와 자동 조치 워크플로를 구분한다.
- 관련 VM·Windows·WSL/Docker 시계가 기준과 1초 이내인지 실제 결과를 남긴다. 시간 서비스 실행만으로 동기화 완료라고 하지 않는다.
- 새 zz_ 계정·승인된 실제 출발지·새 시험 파일을 사용한다. 앞 시험의 잠금·차단·집계 영향이 없어야 한다.
- 코드 커밋·정책·워크플로·센서 상태와 시작 전 상태를 증적으로 남긴다. VM 스냅샷과 설정/경보 상태 파일 기록은 별개이므로 실제 생성한 것만 표시한다.
- 담당이 **설정 동결**을 알린 뒤 시작한다. 측정 중 재시작·규칙·로그 경로·시간 설정 변경이 필요하면 측정을 중단하고 시작 조건부터 다시 확인한다.

수집이 안 되는 상태에서 공격 후 “이벤트 없음”을 캡처해 보강 전 성공으로 처리하지 않는다. 기존 앱의 인증·안전 정책은 승인 없이 해제하지 않는다.

## 6. B의 오후 할 일 · 먼저 할 순서

1. **시계·경로 준비:** B Windows/Kali 오차가 남아 있어 측정 전 해결·재측정. A의 오늘 VPN 주소와 .2→.100:12201/UDP 규칙을 대조한다.
2. **공통 GELF 확인 지원:** A의 설정 완료 연락을 받으면 단일 GET, KST 시각·HTTP 응답과 A/D 원본 대조를 지원한다. GELF_ENABLED=0 상태에서 보강 전 공격을 먼저 보내지 않는다.
3. **S7 실행 지원:** 요청된 실제 시험 파일 접근을 담당과 순서 조율해 1회 실행하고 출발지/시간 증거 제공. C 동결 동안 pfSense·VPN·Suricata·시간 설정을 바꾸지 않는다.
4. **C→D 프로토콜 점검:** 별도 기록의 TCP 중계 전환 보고와 오전 UDP 5514 규칙을 구분한다. 실제 현재 입력·게시·허용 규칙·새 TCP 연결을 확인한다. 보고된 경보 6건 수신을 이후 재접속 성공으로 확대하지 않는다.
5. **S8/S10 수집 준비:** 실전 입력에 쓸 NIDS 서명·원본과 경계 filterlog가 D에서 추출되는지 먼저 확인한다. 오전 시험용 SID 9901022는 정리했고 S8/S10 규칙으로 재사용하지 않는다.
6. **A 실행 환경:** 최소 SSH 전용 계정·공개키·A만 접근하는 경로와 .11~.19 출발지 선택/반환 경로를 따로 준비하되, 측정 동결 중에는 바꾸지 않는다. 계획과 실제 설정 완료를 구분한다.
