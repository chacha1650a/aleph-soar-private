# 수업 Graylog 화면 참고 · 2026-10-20 수신

김명준이 이 채팅에 첨부한 Graylog 목록 화면 3장을 보존하고, 읽을 수 있는 내용만 정리한다. 날짜는 자료를 받은 날이며 촬영 시각·Graylog 버전·설정한 PC는 확인되지 않았다. 화면의 설명은 수업 설정에 적힌 내용이며 실제 대응 성공을 검증한 결과가 아니다.

`System notification events`는 시스템 예약 항목이며 Not Scheduled로 표시된다. 화면의 enabled·Last matched 표시는 설정 상태·매칭 표시일 뿐, 해담시청에서 실행했거나 효과 확인·원복까지 끝냈다는 증거가 아니다.

## 해담시청 기획서에 적용한 판단

- 수업 S11은 Snort 포트스캔이다. 기존 팀 VPN 확장은 `VPN-01`로 구분하고 필수 4종과 팀 S12는 유지한다. Snort를 필수 도구로 추가하지 않으며 NIDS는 기존 Suricata 계획을 유지한다.
- 수업 이벤트의 설명·임계 표기·검색 범위가 다른 곳은 실제 이벤트 조건을 확인하기 전 같은 의미라고 간주하지 않는다. 예를 들어 404 설명은 60초인데 검색 범위는 30초다.
- S1은 집계 창과 실행 주기가 모두 30분으로 보인다. 해담시청에서는 두 값을 따로 정하고 실행 주기가 탐지 지연에 미치는 영향을 기록한다. 수업 화면의 “8회↑”만으로 실제 연산자가 `>`인지 `>=`인지 단정하지 않는다.
- 수업 심야 시간은 00~05시, 기획서의 확장 S2는 22~06시다. 기획서 기준을 이번 자료만으로 바꾸지 않는다. Wazuh의 templates 경로도 해담시청의 실제 웹 루트·bind mount 경로와 구분한다.
- 그림만으로 대응 봇 108·111~117의 실제 URL·포트나 번호 충돌 여부를 확인할 수 없다. 수업 가이드 번호와 팀 내부 번호를 구분해 유지하고 연결 때 실제 경로를 확인한다.
- 사진은 수업 참고 증적이다. 해담시청의 로그 수집·탐지·n8n 대응·효과·원복은 랩에서 별도 시험한다.
