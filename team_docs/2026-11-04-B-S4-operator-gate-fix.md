## 문제와 범위

REPEAT02는 자동 잠금 뒤 `LOCKED` 확인 단계에서 ValueError로 끝났다. 원문 JSON에 입력 문자열이 없으므로 정확한 오타는 확정하지 않는다. 코드에서는 대문자 `LOCKED`와 정확히 일치하지 않으면 종료하고, 인증 세션 정리 로그아웃을 시도한다. 프로세스 종료로 같은 옛 세션을 이용한 후속 검증을 이어갈 수 없었다.

이번 회차 결과는 **자동 잠금 확인·효과 일부 미검증·별도 복구·티켓 종료**다. 원래 세션과 잠금 중 재로그인은 미검증이며, C 효과 완료 ACK가 없고 A 재설정 뒤 D 효과 기록이 저장됐다. 수정본이 과거 결과를 통과로 바꾸지는 않는다.

## 변경

- LOCKED/UNLOCKED/NO_LOCK에 앞뒤 공백 제거·대소문자 정규화 적용.
- 빈 입력·오타·다른 단계 토큰이면 같은 프로세스에서 다시 대기. 이 루프는 네트워크 요청이나 인증 세션 정리를 하지 않는다.
- STOP/Ctrl+C/EOF는 중단으로 기록. 기존 1회 세션 로그아웃 정리 외 공격·관리자 API 호출은 추가하지 않는다.
- `operator_gates`에 확인 단계·시각·잘못된 입력 횟수와 상태를 기록하고, 중단 시 `error_code`를 남긴다. 입력 원문·예외 메시지·비밀번호·쿠키는 기록하지 않는다.
- UNLOCKED 안내에 D 효과 기록 → C ACK → A 재설정 확인 순서를 명시. 외부 상태를 도구가 자동으로 확인하지는 않는다.
- 기존 실행본은 `lab/preserved/20261104/s4_session_round.py`에 바이트 그대로 보존한다. SHA256 `e9a233715680288f733ba8eb5e86f2d7ccd519dbdaeeb850ad9d4442a759f5af`.
