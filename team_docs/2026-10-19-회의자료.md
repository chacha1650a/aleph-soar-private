> **공공기관 민원 서비스·원격 유지보수 접속 보안 관제 및 자동 대응 시스템**

## 3. 공통 환경 구축 기준

모두 같은 기준으로 만들어야 나중에 하나로 합칠 수 있습니다.

### ① 저장소 (오늘)

```powershell
git clone https://github.com/NoBugs-Aleph/aleph-soar-capstone.git
```

- `main`에서 시작합니다. 작업은 브랜치를 만들어 PR로 올리고, main에 직접 push하지 않습니다.
- 하루를 마칠 때 자기 [개발 일지](../docs/devlog/members/)(`docs/devlog/members/<닉네임>.md`)를 갱신합니다.
- 비밀번호, API 키, Wazuh 관리자 비밀번호 같은 값은 Git에 올리지 않습니다.

### ② 가상화 (이번 주)

VMware Workstation과 강사님이 말한 VMnet 내부망을 씁니다. 아래 배정은 초안이며 **밴드 토폴로지를 보고 확정**합니다.

| VMnet | 구역 | 대역(초안) | 들어가는 것 |
| --- | --- | --- | --- |
| VMnet8(NAT) | 설치용 인터넷 | 기본값 | 패키지 설치 때만 연결 |
| VMnet2 | 외부(공격·외주) | 203.0.113.0/24 | Kali, 외주 업체 PC |
| VMnet3 | DMZ | 10.10.10.0/24 | 민원 포털 |
| VMnet4 | 업무망 | 10.10.20.0/24 | 업무 시스템, MySQL |
| VMnet5 | 관리망(관제) | 10.10.30.0/24 | Graylog, Wazuh, n8n |
| (VPN) | 외주 VPN | 10.10.40.0/24 | pfSense OpenVPN 대역 |

- 필요한 VM: pfSense(구역마다 NIC 하나), 관제 서버(Graylog·Wazuh·n8n), 서비스 서버(Docker로 Flask + MySQL), Kali
- 모든 VM의 시간대는 **KST**로 맞추고, 같은 NTP를 씁니다.
- 테스트 계정은 `zz_`로 시작하고, IP는 위 대역만 씁니다. 격리된 실습망 밖으로 공격 트래픽을 보내지 않습니다.

### ③ 미리 알아 둘 문제: PC 메모리

Wazuh 공식 권장 사양만 해도 RAM 8GB입니다. 여기에 Graylog, pfSense, Kali, 앱까지 올리면 **16GB PC 한 대로는 부족할 가능성이 큽니다.** 그래서 오늘 PC 사양을 받아 "한 PC에 전부"로 갈지 "관제 PC와 서비스 PC로 나눌지"를 정합니다.
