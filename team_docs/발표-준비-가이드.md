## 3. 말하는 방법 (전원 공통)

- **숫자는 분자·분모 같이**: "5번 중 5번 차단"이지 "100%"만 말하지 않는다. 안 잰 것은 "아직 측정하지 못했습니다".
- **내가 한 것과 팀이 한 것 구분**: "이 부분은 B가 만들었고, 저는 연결과 검증을 맡았습니다."
- **observe(dry_run)와 실제 대응 구분**: dry_run 시험은 "탐지와 워크플로 호출까지 확인, 실제 차단은 아직"으로 말한다.
- **시연 실패 멘트 준비**: "탐지 주기가 1분이라 잠시 걸립니다. 기다리는 동안 같은 흐름을 미리 녹화한 화면으로 보여드리겠습니다."
- **화면 가리기**: 비밀번호·`X-Response-Key`·세션·`.env`·VPN 프로필이 보이는 창은 녹화 전에 닫는다.
- **모르는 질문**: "그 부분은 확인 후 정확히 답변드리겠습니다." 지어서 답하지 않는다.
- 공지의 단계별 예시 문구를 뼈대로 쓰고, 아래 개인별 내용으로 ○○을 채운다.

   - S4(11/03 1회): 실패 5 → 성공 뒤 6.975초 자동 잠금·세션 회수, 오잠금 0, 비밀번호 재설정 원복.

6. **개선 방향**: 해제를 승인 워크플로로 자동화(지금은 수동), n8n 웹훅 수신 인증, 여러 출발지로 나눈 공격 탐지, S4 해제 직후 오입력 재잠금 억제.

5. **해결책 후보**: TCP 입력 생성·스트림 규칙 정리 / DB·검색 엔진 먼저, VPN 연결 뒤 Graylog 시작 순서로 고정 / dry_run 기록은 30분 안의 것만 세도록 수정(#114).
6. **개선 방향 후보**: S12 실제 대응·회복 측정, 기준선 2(정상 출발지) 확정, n8n 웹훅 인증, 설정 내보내기·버전 관리.
7. **예상 Q&A 후보**: 요청 수만 많고 느려지지 않으면? (대응 안 함 — 11/02 실측) / 정상 사용자가 몰리면? / 공격을 멈춘 효과와 차단 효과를 어떻게 구분?

## 6. 리허설(11/5)용 짧은 문구

공지 예시 그대로 쓴다. 각자 ○○만 채운다.

> "NoBugs ○○○, ○○ 담당입니다. 제가 맡은 ○○ 기능을 바로 시연하겠습니다."
> (시연 후) "공격 → 탐지 → 자동 대응 → 복구까지 확인했습니다. 담당 파트는 ○○이고, 본발표 때 코드와 문제 해결 과정을 자세히 설명하겠습니다."

실제 대응을 못 보여 주는 케이스는 "→ 자동 대응(현재 dry_run)"처럼 범위를 말한다.
