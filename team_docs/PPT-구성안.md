| 부분 | 내용 | 리허설 11/5 | 본발표 11/6 |

공지에 팀 공통 파트는 없다. 아래 공통 4장은 2부 앞에 두는 **제안**이며, 발표자·시간은 팀이 정한다.

### 1부 라이브 테스트 (L)

슬라이드는 순서표 1장(L1)만 두고 실제 화면으로 진행한다. 순서는 공격 흐름대로 제안: **B(S8·S10 스캔·침입) → A(S1 계정 추측) → C(S7 변조) → D(S12 폭주)**. 케이스마다 공지 필수 장면 ① 공격 ② Graylog·Wazuh 탐지 로그 ③ 규칙 발동 ④ n8n 실행 ⑤ 차단·인시던트(대시보드) ⑥ 정상 동작 ⑦ 해제·원복을 짚는다. 실패 대비 녹화·캡처를 케이스마다 준비하고 촬영 시점을 표시한다.

모든 담당이 같은 7장 형식을 쓴다. 장 번호는 `P-자리-단계`(예: P-A-4).

| 장 | 제목 | 담을 것 | 주의 |
| --- | --- | --- | --- |
| 1 | 소개 | 이름, 자리, 담당 케이스·원칙, 맡은 시스템 | — |
| 2 | 기능 구현 | 흐름도 1장 + 1부 시연 핵심 캡처(또는 짧은 녹화) + 실측 수치(n/N, 시간) | 미측정은 미측정으로 |
| 3 | 코드 리뷰 | 화면 1개 + 백엔드(또는 규칙·워크플로) 1개 발췌, 인상 깊었던 이유 | 본인이 작성·검증한 코드 중심 |
| 4 | 문제점 | 증상 → 원인, 숫자 있는 사례 1개(+보조 1개) | — |

| 7 | Q&A | 마무리 문구. 예상 질문 3개는 발표자 메모 | — |

## 개인 섹션 작성 기준 (케이스 공통 틀)

②~⑥을 채울 때 아래 여섯 가지가 빠지지 않게 한다. 한 장에 안 들어가는 로그·설정 원문은 부록으로 뺀다.

1. 보호 자산과 공격 입력: 출발지·대상·조건을 재현 가능한 수준으로.
2. 탐지: 로그 소스, 집계 키·시간 창·임계값, 정상과 구분하는 기준.
3. 대응: n8n이 호출한 대상과 실제 수행한 차단·잠금·복구.
4. 효과: API 성공 응답이 아니라 실제 접근 차단·세션 무효·파일 복구·정상 서비스 동작.
5. 티켓·원복: 사건 기록과 해제·복원 뒤 정상 동작.
6. 결과: 시험 횟수·성공 수·시간·오탐·미탐과 미검증 부분.

## 공통 주의

- 그림·구성도에는 실제 사용한 도구와 최종 배치만. 과거 두 PC 구상과 섞지 않는다.
- 캡처·로그·라이브 화면에 비밀번호·토큰·쿠키·`X-Response-Key`·VPN 프로필·`.env`·원문 개인정보를 넣지 않는다. 가공한 캡처는 가림·발췌 여부를 표시한다.
- 계획 수치(목표 MTTD, 시험 67회 등)를 실측 성과로 옮기지 않는다.
