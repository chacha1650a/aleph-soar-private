## A 구현·D 입력에서 맞출 사항

- GELF TCP는 **비압축 JSON + 메시지마다 NUL(0x00) 구분자**다. Suricata Raw TCP의 LF 구분을 그대로 사용하지 않는다. D 실제 버전의 GELF 입력 옵션과 맞춰 검증한다.
- TCP는 전송 중 패킷 재전송을 제공하지만 연결 실패·프로세스 종료·수신/색인 실패를 포함한 종단 간 무손실을 보장하지 않는다. 송신 성공을 D 색인 성공으로 집계하지 않는다.
- 단순 소켓 교체·짧은 timeout만으로 장애 시 로그가 자동 복구되지는 않는다. A의 로컬 JSONL을 원본으로 유지하고 요청 처리 경로와 재연결/재시도를 분리하는 방향을 권고한다. 큐/보관의 한도·실패/초과 시 처리·재시작 복구 정책을 구현 전에 명시한다. 웹 요청 안에서 재시도를 반복하지 않고 포털 응답시간을 실제 측정한다.
- 재시도는 같은 event_id·원본 발생 시각을 보존한다. 중복은 가능하므로 unique event_id와 raw 수신 건수를 따로 센다. 전환 시 시작 커서를 정하고 과거 JSONL 전체를 측정 스트림에 임의 재전송하지 않는다. 과거 누락 복구가 필요하면 측정 구간/정의 동결과 별도로 조율한다.
- 이번 목표는 전송 방식 변경이다. 이벤트 의미·상관 키는 유지하며 변경이 필요하면 별도 공통 계약 절차로 원본·소비자를 함께 갱신한다.

공식 근거: [Graylog GELF Format](https://go2docs.graylog.org/current/getting_in_log_data/gelf_format.html)의 GELF via TCP 및 전송 장애 설명. 현재 페이지는 최신 Graylog 문서이므로 D 운영 버전의 UI 옵션을 그대로 가정하지 않는다.

2. D 수신 중단·복구를 별도 준비 시험으로 실행해 포털 HTTP/지연, 보관·재연결·재시도, 복구 후 원본 ID 도착/중복과 잔여 누락을 확인한다. 중단 시간·부하·지연 허용 기준은 실행 전에 A/D와 정한다. 운영 입력 중 임의로 D를 중지하지 않는다.
3. 전환한 입력에서도 .21/.22 실제 src_ip·전체 event_id·원본 시각·기존 rule/stream 파싱을 대조한다. 오늘12:24의 기존 UDP health 대조는 과거 준비 근거로 보존하되 TCP 수신 검증으로 대신하지 않는다.
4. A/D/B 검증 뒤 수집 방식을 동결하고 B S8/S10·D S12 보강 전을 TCP로 시작한다. 정의/자동 대응 보강 전 상태·검색 주기·수집 지연 상한 등 기존 선행 조건은 계속 필요하다.

## 평가·복귀 기준

- S1/S4의 유효 UDP 보강 전 결과는 보존한다. TCP 전환 시점·배포/설정 버전·누락/중복·재시험 사유를 보강 변경 목록과 정량 리포트에 적는다.
- UDP 전과 TCP 후를 비교하면 수집 개선 효과가 함께 포함된다. 이를 탐지 규칙만의 개선 효과로 주장하지 않는다. 규칙 효과를 분리해 평가해야 한다면 동일 TCP 수집 조건의 추가 보강 전 기준선을 A/D와 별도 결정한다. B가 기존 S1/S4를 자동으로 다시 실행하지 않는다.
- 수집 누락·예상 밖 응답·시계/설정 변경이 있는 실행은 탐지 실패와 구분해 미관측/측정 중단 사유를 기록한다. 원본을 고쳐 맞추지 않는다. 복귀는 측정 중단/마감 뒤 설정·프로토콜을 명시하고 수행한다.
