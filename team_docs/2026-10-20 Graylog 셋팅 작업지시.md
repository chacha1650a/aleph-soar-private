## 보강 전 시험이 먼저입니다 (10/20 A 확인)

- 팀은 탐지 규칙을 **보강하기 전과 후로 나눠 평가**합니다. 각자 자기 케이스를 보강 전 1회, 보강 후 9~11회 시험합니다([정량평가 설명서](https://github.com/NoBugs-Aleph/aleph-soar-capstone/blob/docs/quant-evaluation/team_docs/정량평가_설명서.md) 4장, PR #23).
- 보강 전 = 로그는 Graylog에 들어오지만 **내 케이스의 이벤트 정의와 n8n 대응은 아직 없는** 상태입니다. 규칙을 한 번 넣으면 이 상태로 되돌리기 어렵습니다.

- 순서: 이 셋팅 완료 → 각자 보강 전 시험(설명서 4-2) → 자기 케이스 규칙 작성(보강) → 보강 후 시험

## 할 일

### 1. 저장소에 compose 추가

main에서 새 브랜치를 만들고 `infra/graylog/`에 `docker-compose.yml`, `.env.example`, `README.md`를 둡니다. 수업 compose를 바탕으로 하되 아래를 바꿉니다.

| 항목 | 값 | 이유 |
| --- | --- | --- |
| 이미지 | `graylog/graylog:6.1.16`, `mongo:6.0.28`, `opensearchproject/opensearch:2.5.0` | 학원 PC에서 동작을 확인한 조합입니다. 버전을 정확히 고정합니다. OpenSearch 2.15는 색인 오류가 납니다(수업 메모) |
| 금지 설정 | `GRAYLOG_ELASTICSEARCH_VERSION`은 넣지 않음 | 넣으면 색인이 거부됩니다(수업 메모) |
| 시간대 | `GRAYLOG_ROOT_TIMEZONE=Asia/Seoul`, `TZ=Asia/Seoul` | 없으면 UTC라 KST와 9시간 어긋납니다 |
| 힙 | OpenSearch `-Xms1g -Xmx1g`, Graylog `GRAYLOG_SERVER_JAVA_OPTS=-Xms1g -Xmx1g` | 수업 구성은 Graylog 힙을 정하지 않았습니다 |
| 메모리 제한 | OpenSearch 2g, Graylog 2g, MongoDB 512m (시작값) | 기획서 ③ "컨테이너별 메모리 제한". 측정한 뒤 고칩니다 |
| 포트 | 웹 `127.0.0.1:9000:9000`, GELF `12201:12201/udp`, Syslog `514:1514/udp` | 기획서 ③: 웹 화면은 관제 PC 안에서만 열고, 로그는 12201/udp와 514/udp로 받습니다. 입력이 없는 GELF TCP는 열지 않습니다 |
| 이름 | compose `name: haedam-soc`, 네트워크 `soc-net` | 수업 컨테이너(`gl-*`)와 이름이 겹치지 않게 합니다. 나중에 n8n·Wazuh가 같은 네트워크에 붙습니다 |
| 재시작 | `restart: unless-stopped` | |
| 비밀값 | `.env`에만 두고 `.gitignore`에 추가. 커밋은 `.env.example`만 | 관리자 비밀번호는 본인이 직접 정합니다 |

### 2. 같은 PC의 수업 구성과 충돌 정리

수업 Graylog가 떠 있으면 9000·12201·1514 포트가 겹칩니다. `docker stop gl-graylog gl-opensearch gl-mongo`로 **멈추기만** 합니다. `docker compose down -v`나 볼륨 삭제는 하지 않습니다(수업 자료 보존).

### 3. Docker 메모리 (본인 확인 후)

- `.wslconfig`의 `memory`를 기획서 계획값인 10GB로 올립니다. 적용하려면 `wsl --shutdown`이 필요하고, 이때 Docker 전체가 재시작됩니다.
- `vm.max_map_count`가 262144 이상인지 확인합니다: `wsl -d docker-desktop sysctl vm.max_map_count`

### 4. Graylog 화면 설정 (최소)

- 입력 2개: `haedam GELF UDP`(12201), `pfSense Syslog UDP`(1514)
- 스트림 `haedam-portal`: 조건은 `source` = `haedam-portal`입니다. 포털 규칙이 게시판 로그와 섞이지 않게 하는 기반입니다.
- System → Content Packs로 입력·스트림**만** 내보내 `infra/graylog/content-pack.json`에 커밋합니다. 관제 PC가 바뀌어도 그대로 가져올 수 있습니다. 이벤트 정의·알림은 넣지 않습니다(보강 전 상태 유지). 커밋 전에 비밀값이 없는지 확인합니다.

### 5. 확인 (완료 기준)

- [ ] `docker compose ps`에서 세 컨테이너가 실행 중이고, `http://127.0.0.1:9000/api/`가 6.1.16을 응답하며, OpenSearch 상태가 green
- [ ] 고유 문자열을 넣은 표식 로그를 GELF 1건, Syslog 1건 보내서 각각 검색됨
- [ ] 포털 로그: backend `claude/portal-ip-block-file-key` 브랜치를 `GELF_ENABLED=1`로 실행하고 로그인 실패 1회 → `haedam-portal` 스트림에서 `rule:login-bruteforce`가 보이고, `event_id`·`event_type`·`src_ip`·`username` 필드가 있음
- [ ] `docker compose restart graylog` 뒤 새 표식 로그가 다시 들어옴
- [ ] `docker stats --no-stream`과 호스트 RAM 사용량 기록
- [ ] Alerts → Event Definitions에 케이스 규칙이 없음(보강 전 상태)
