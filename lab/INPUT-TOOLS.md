# B 입력 도구: S4·S8·S10

이 문서는 11/03 사용한 입력 도구를 저장소에서 추적하기 위한 안내다. 11/03 원본은 [해시 목록](input-tools-provenance.json)에 고정해 보존했다. 11/04 S4 인자화 사본과 S8/S10 오류 기록 보강본은 별도 항목으로 구분한다. **코드 보존·오프라인 테스트·실제 장비 시험은 서로 다른 완료 조건**이다. 실측 증적과 비밀번호·쿠키·토큰은 이 변경에 포함하지 않는다.

## 기본 실행: 입력 없음

준비된 프로젝트 Python으로 아래 명령을 실행할 수 있다. S4는 계획만 출력하고, S8/S10은 지정한 새 파일에 오프라인 계획만 쓴다. 기존 계획 파일은 덮어쓰지 않는다.

```powershell
.\.venv\Scripts\python.exe lab/s1s4/s4_session_check.py
.\.venv\Scripts\python.exe tools/s8s10_input.py --case S8 --run-id PLAN-S8 --target http://10.250.0.2:5000 --out "$env:TEMP\aleph-PLAN-S8.json"
.\.venv\Scripts\python.exe -m pytest tests/test_b_input_tools.py -q
```

마지막 검사는 HTTP 응답을 메모리 어댑터로 대체하고 실제 소켓을 금지한다. 실제 포털·PF·Graylog·n8n·C API에 요청하지 않는다. 새 테스트는 별도 포털 저장소를 설치하지 않는다. 과거 B의 별도 백엔드 리허설과 이번 합성 검사를 같은 결과로 합치지 않는다.

## S4: 회차가 고정된 세션 검증

위치: [s4_session_check.py](s1s4/s4_session_check.py).

- 고정값: `S4-20261103-LIVE01`, 포털 `10.250.0.2:5000`, 대상 `.17/zz_s4_1103`, 정상 `.100/zz_n1`.
- 이 회차는 이미 끝난 기록이다. 같은 코드의 `--execute`를 다시 실행해 과거 결과를 대체하지 않는다. 다음 회차는 새 회차 ID·계정 상태·시각을 별도 검토하고 D 공동 GO를 받은 뒤 진행한다. 이 PR은 다음 회차 설정을 새로 결정하지 않는다.
- 실제 실행은 Kali/Linux의 대화형 TTY에서만 허용한다. `--execute`, 합의한 `--unlock-method reset` 또는 `keep`, 회차 확인이 필요하다. `--confirmed-run`은 입력 편의용 확인값이며 D GO를 자동으로 확인하는 기능은 아니다.
- 예약 실행에는 시간대가 포함된 `--start-at`과 `--latest-start`를 함께 준다. 비밀번호 준비 후 시작 창이 지났으면 입력 없이 거절한다. 이 옵션을 생략하면 시각 예약은 적용되지 않는다.
- 대상과 정상 계정 비밀번호는 `getpass`로 입력한다. 암호·쿠키·CSRF는 메모리에서만 사용한다. 비밀번호를 명령행·채팅·환경 파일에 넣지 않는다.

흐름은 세션/CSRF 준비 GET → 실패 로그인 5회 → 성공 로그인 1회(로그인 시작 간 60초)다. 준비 GET의 지연 때문에 첫 실패 로그인은 T0보다 늦을 수 있다. 성공 시점의 쿠키를 별도 메모리에 보존한다.

`LOCKED`는 D/A의 실제 잠금 확인 뒤 입력한다. 같은 옛 세션 `/api/v1/auth/me`가 **200 + user:null**, 기존 비밀번호 로그인은 401인지 확인한 뒤 정상 사용자의 로그인·민원 목록·로그아웃을 확인한다.

`UNLOCKED`는 **B 효과 전달 → D stage=effect 저장 → C ACK → A 실제 재설정/해제 확인** 뒤 입력한다. 프로그램 자체가 외부 ACK를 조회하지 않으므로 이 순서는 운영자가 지켜야 한다. 옛 세션의 무효 유지, 새 비밀번호 로그인 및 로그아웃을 확인한다. 재설정 비밀번호도 TTY에서만 입력한다.

기본 성공 경로는 준비 GET을 포함해 HTTP 16회다. 실패 시 추가 시험 입력은 중단하지만, 이 프로그램이 만든 로그인 세션이 남아 있으면 해당 세션의 로그아웃을 한 번 시도할 수 있다. 이는 실패 요청의 재시도가 아니다. 잠금·해제·관리자 API는 호출하지 않는다.

증적은 현재 작업 폴더의 `<고정 회차>-client.json`이다. 기존 파일이 있으면 시작을 거부한다. 요청 시각·출발지·상태·검사 결과를 저장하며 응답 본문 전체는 보존하지 않는다. `complete=true`는 클라이언트 검사 완료일 뿐 티켓 종료·활성 조치 0의 증명이 아니다. 실패 결과도 보존하고 A/C/D와 원복을 대조한다.

## S8/S10: 제한된 입력 생성

현재 도구: [s8s10_input.py](../tools/s8s10_input.py). Monday r5 실행 원본은 [보존 사본](preserved/20261103/s8s10_input.py)으로 이동했으며 원본 SHA256은 불변이다. 현재 도구는 실패 시 report.error에 phase/type만 남기고 finished_at을 저장한다. CSRF 비JSON·잘못된 구조와 ICMP timeout도 미완료로 보존하며 오류 원문·응답·비밀값은 기록하지 않는다.

| 항목 | S8 | S10 |
| --- | --- | --- |
| 출발지 | 203.0.113.21 | 203.0.113.22 |
| HTTP | GET 스캔 404 → GET auth/me 200 → POST 로그인 401 | 동일 |
| ICMP | 없음 | HTTP 3건 성공 뒤 .22 → 203.0.113.1 echo 1회 |
| 자동 재시도 | 0 | 0 |

허용 origin은 `http://203.0.113.1`과 `http://10.250.0.2:5000`이다. 기본값은 전자이므로 직접 포털 회차에서는 반드시 후자를 명시한다. 자격 증명·경로·query·fragment가 든 URL은 거절한다. 회차 ID는 영숫자로 시작하는 영숫자·밑줄·하이픈 최대 40자다.

실행 시 `--execute`가 필요하며 Windows에서는 거절한다. 이 도구에는 예약·외부 GO 확인 기능이 없으므로 D가 지정한 입력 창에 운영자가 실행한다. `.100` 정상 업무 확인이나 PF 차단·해제를 수행하는 도구가 아니다. **PF ACCEPT01/02 단독 인수에는 이 도구를 사용하지 않는다.** 단독 인수에는 별도 GET /login probe를 사용한다.

오프라인 계획의 `--out`을 실제 입력 결과로 재사용하면 기존 파일 보호로 거절된다. 실제 실행에는 합의한 회차의 새 결과 파일을 지정하되, 부분 실행 실패를 새 이름으로 다시 실행하지 않는다. 실패 증적을 보존하고 D와 처리 상태부터 대조한다. HTTP 오류는 즉시 중단하며, S10의 ICMP 응답 없음만으로 PF 로그 수신이나 차단 성공을 판정하지 않는다.

11/03 S8 LIVE01은 웹훅 미등록으로 대응 실패, LIVE02는 실제 티켓·차단·사람 해제·복구까지 대조했다. **S10 탐지·실제 티켓 본 시험은 이 변경 준비 시점에 미실행**이다. 합성 S10 검사 통과는 실제 완주 결과가 아니다.

## 11/04 S4 반복·경계용 사본

[s4_session_round.py](s1s4/s4_session_round.py)는 단독 파일로 전달할 수 있다. 기존 s4_session_check.py는 바이트·해시 그대로 유지한다. 새 도구는 `--run-id`, `--account`, `--source`, `--failure-count`가 필수다. 대상은 합의한 시험 계정 zz_ 및 203.0.113.0/24 출발지만 사용하고 Kali 호스트 .10·정상 대조/보호 대상 .12·정상 .100은 출발지로 거절하며 정상 계정 zz_n1도 대상 계정으로 사용할 수 없다. 포털 목적지와 로그인 간격 60초는 기존과 같다.

오프라인 예시(계정 생성·출발지 할당·GO를 뜻하지 않음):

```sh
python lab/s1s4/s4_session_round.py --run-id S4-20261104-REPEAT02 --account zz_s4_repeat02 --source 203.0.113.17 --failure-count 5
python lab/s1s4/s4_session_round.py --run-id S4-20261104-EDGE01 --account zz_s4_edge01 --source 203.0.113.17 --failure-count 4
```

실제 실행은 새 계정/실패 이력·출발지·탐지창 잔여·A/C/D 직전값·관측 종료와 GO를 확정한 뒤 Kali 대화형 TTY에서 `--execute --confirmed-run <동일 회차 ID>`를 추가한다. 예약에는 시간대 포함 `--start-at`과 `--latest-start` 둘 다 지정한다. 비밀번호는 TTY에서만 받는다. 원본 11/03 회차 ID와 기존 결과 파일은 거절한다. 회차 2~5도 각각 독립 실행하며 자동 반복하지 않는다.

회차 간 입력 합산 방지:

- 회차마다 **새 시험 계정**을 사용하는 것을 우선한다. 경계(실패 4 + 성공 1) 직후 같은 계정으로 발동 회차를 이어 실행하면 10분 검색창에서 입력이 합쳐질 수 있다. 회차 ID만 바꾸어도 계정·출발지 그룹의 과거 이벤트는 분리되지 않는다.
- 같은 계정을 재사용하려면 이전 회차의 마지막 관련 이벤트부터 **최소 10분 이상** 간격을 두고, D가 실제 검색 시각 필드·10분 창에서 이전 입력이 제외됐음을 확인한 뒤 새 GO를 발행한다. 정확히 10분이 지났다는 로컬 시계만으로 시작하지 않는다. A 계정·세션·실패 이력 및 C 열린 티켓/활성 조치도 다시 대조한다.
- D의 S4 정의는 계정명이 고정되어 있으므로, **새 계정으로 바꿀 때 D가 정의의 계정 조건을 해당 --account 값과 맞춰 반영·확인**해야 한다. B 도구는 정의를 변경하지 않는다. A 계정 준비 → D 정의/기존 창 확인 → C 직전값 → 개별 GO 순서를 합의한다.

- 실패 5회: 성공 뒤 `LOCKED` 대기 → 옛 세션 무효·401·정상 업무 → D 효과/C ACK와 A 재설정 완료 뒤 `UNLOCKED` → 옛 세션 무효 유지·새 로그인·로그아웃. `--unlock-method reset` 기본, 비밀번호 유지 해제로 합의한 경우만 `keep`.
- 실패 4회: 성공 뒤 합의한 관측 종료까지 기다리고 D/A/C의 탐지·티켓·잠금 미발생 확인 후 `NO_LOCK` 입력 → 같은 세션의 사용자 유지·정상 업무·양쪽 로그아웃. LOCKED/UNLOCKED나 비밀번호 재설정을 요구하지 않는다. 기본 HTTP 12회이며 예상 밖 잠금 시 실패로 중단한다.
- `NO_LOCK`은 운영자 확인이다. 관측 종료 뒤 A가 해당 계정·시각 구간 원본의 `auth.account_locked` 없음과 DB `locked=0`을 확인 시각과 함께 별도 회신한다. D의 탐지 미발동 및 C의 신규 티켓/활성 잠금 없음 근거도 같은 회차에 연결한다. 도구가 Graylog/C/포털 DB를 조회해 미발동을 증명하지는 않는다. 로그인 후 무관한 요청을 추가해 시험 창을 늘리지 않는다.

### 운영자 확인 입력과 중단

인자형 `s4_session_round.py`의 `LOCKED`·`UNLOCKED`·`NO_LOCK` 입력은 앞뒤 공백과 대소문자를 무시한다. 빈 줄·오타·다른 단계의 확인어는 요청을 보내지 않고 같은 자리에서 다시 기다린다. 이 대기 중에는 원래 세션을 메모리에 유지하며 HTTP 재시도나 추가 로그인을 하지 않는다. 입력 문자열 자체는 결과 파일에 저장하지 않고, `operator_gates`에 단계·시각·잘못된 입력 횟수·확인/중단 상태만 남긴다.

외부 확인이 끝나기 전에는 확인어를 입력하지 않는다. `UNLOCKED`는 **D 효과 기록 → C 효과 ACK → A 실제 재설정**까지 확인한 뒤 입력한다. 운영자 확인은 외부 상태를 직접 조회한 증거가 아니며, 자동으로 다음 단계로 넘어가지 않는다.

중단하려면 `STOP` 또는 Ctrl+C를 사용한다. EOF(터미널 입력 종료)도 미완료로 처리하고 고정된 `error_code`를 남긴다. 기존 실패 정리 로직이 이 도구에서 만든 인증 세션에 한해 로그아웃을 최대 1회 시도할 수 있다. 계정 잠금을 해제하거나 관리자 API를 호출하지 않으므로 A/D/C와 실제 복구를 별도로 진행한다. 프로세스를 강제 종료하면 이 기록도 보장되지 않으며, 원래 세션을 잃은 회차를 재실행해 같은 세션 검증으로 대신하지 않는다.

11/04 REPEAT02는 기존 실행본이 LOCKED 확인 단계에서 ValueError로 중단된 회차다. 당시 입력 문자열은 보존되지 않았으므로 정확한 오타는 확정하지 않는다. [해당 실행본](preserved/20261104/s4_session_round.py)은 e9a23371… 해시로 보존했다. 이 수정은 다음 회차용이며, 기존 JSON·부분 검증 판정·원본 `s4_session_check.py`를 변경하지 않는다.
- complete는 클라이언트 검사만 뜻한다. 오류 시 해당 도구가 만든 세션의 로그아웃을 한 번 시도할 수 있으나 잠금·해제·관리자 API 및 자동 재시도는 없다. 원본 응답·쿠키·비밀번호는 저장하지 않는다.

합성 검사: `python -m pytest tests/test_b_input_tools.py tests/test_b_input_followup.py -q`. 실제 장비 재인수·배포·추가 회차는 아직 수행하지 않았다.
