## 4. 최신 설계 방향

잠정 주제는 스마트팩토리 생산관리·협력사 계정의 자료 접근 이상과 안전한 업무 복귀 검증입니다.

- 가상 라인 A·B·설비 2개. 생성기→별도 수집 API/계정→DB, 포털은 라인별 자료를 조회.
- 관리자·협력사 정비 담당자·보안/복구 담당자·수집 계정의 권한 분리.
- 침해 대상 계정 잠금·기존 세션 폐기 중에도 정상 직원 업무와 가상 데이터 수집이 유지되는지 시험.
- 복구는 유출 가정 시 비밀번호 재설정, 예전 세션 지속 거부, 신뢰할 권한 기준 복구, 충돌 시 자동 덮어쓰기 중단까지.
- 기본 대응은 계정 단위. 실제 설비 제어·공장 전체 차단·물리 공정 복구는 이번 범위에 없음.
- 4계층 필수는 아직 가정. 엣지·네트워크·앱·데이터의 실제 제어·관찰 증거를 설계하되 샘플을 실제 연결로 기록하지 않음.

## 5. Claude 의견을 반영할 때의 주의점

이 절은 구현 전 검토 기준이며 현재 스키마나 코드에 적용돼 있지 않습니다.

- 재시도가 있으면 T4 중복 안전성 필수. 동일 조치 재시도는 동일 `operation_id`; 해제 후 새 잠금은 새 조치 ID.
- 세션 버전은 잠금·해제 후 이전 세션 거부의 구현 후보. 현재 계정 상태·권한도 요청마다 확인할 설계 필요.
- 반복 실패 후 성공만으로 비밀번호 유출을 단정하지 않음. 시나리오 가정을 명시하고 유출 가정 사례에서 이전 비밀번호 거부를 시험.
- `previous_role` 한 값이나 대응 직전 권한을 무조건 복구하지 않음. 신뢰할 변경 이력·의심 변경 이전 기준·후속 정상 변경 충돌 확인.
- 실패 주입은 동일 조건의 비교 실험으로 유지 가능. 정상 사례와 독립 접근 시험으로 기록 상태/실제 효과를 대조.
- 같은 IP에 현재 정상 사용자가 안 보인다는 사실만으로 IP 전체 자동 차단을 승인하지 않음.
- 요청 ID는 요청 하나의 계층 간 연결용. 여러 요청의 침해 흐름은 계정·자산·시간 순서를 별도로 검증.
- SQL 주석의 ID 보존·DB 감사 결과 필드·원문 값 제거는 제품과 설정의 실제 동작 확인 필요.
