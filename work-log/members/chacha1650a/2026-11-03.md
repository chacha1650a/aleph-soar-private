## 문제와 해결

- S8 LIVE01 웹훅 미등록: CLI `import:workflow`가 웹훅 행을 지우고, CLI `publish:workflow`는 DB 값만 바꿔 실행 중 서버에 웹훅을 등록하지 않음. 오전 810 성공은 기동 시 캐시로 처리된 것으로 추정 → UI 세션으로 재게시. **CLI 반입 뒤에는 UI 게시 + 웹훅 행·키 없는 요청 403 확인**을 절차에 넣음.
- S8 정의가 실패 회차 뒤에도 켜져 있었음 → 웹훅 복구 직후 비활성화하고 LIVE02에서 다시 켬. 같은 출발지는 grace 15분 동안 재알림이 억제되므로 T0를 14:50으로 잡음.
- S4 실제 잠금 불가: 생성기에 `dry_run:false` 전환이 없었음 → #127.
- S4 자격 증명 연결이 저장되지 않음: 반입 전에 열어 둔 편집 탭에서 저장 → 새로고침 후 재저장.
- C가 효과(stage=effect)를 활성 조치가 있을 때만 받음, haedam-40은 관찰 모드 고정이라 실기록 불가 → D 수동 기록 워크플로로 effect·released를 C에 남김.
- PF 837 거절: n8n SSH 노드가 `cd '/' ;`를 앞에 붙임 → cwd 빈 문자열 식으로 수정(#128).
- PF 841·843 결과 대조 필요: 규칙이 runtime·config에 늦게 반영/잔존, 도구 status의 configured 판정이 config 잔존을 놓침 → B 수동 정리. 자동 인수 통과로 집계하지 않음. B r2(readback 대기·판정 보강) 배포 뒤 ACCEPT02 통과.
- ACCEPT02 17:50 T0가 GO 전달 누락으로 입력 없이 지남 → 18:10 상태 재확인 후 18:20으로 다시 잡음.
- n8n CLI `execute`가 task broker 포트 5679 충돌로 실패 → `N8N_RUNNERS_BROKER_PORT=5690`으로 실행.
- A 내보내기 해시가 보고값과 달랐음: Windows에서 CRLF로 저장 → LF로 다시 저장해 보고 해시와 일치. 2차 ZIP(5412dbf8…)은 폐기. Graylog 조회 스크립트가 `S1` 접두어로 S10·S12 정의를 S1 이름으로 저장 → 파일명·스크립트 수정.
- S12 자격 증명: 19:36에 만든 Header Auth의 헤더 Name에 자격 증명 이름이 들어가 있었음(Graylog `X-Haedam-Key`와 불일치) → `X-Haedam-Key`로 수정, 제목 변경. 올바른 키 요청으로 값 일치 확인.
