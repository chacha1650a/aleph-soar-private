### pfSense TRANSIT와 팀 VPN

기존 수업용 WAN VPN(UDP 1194, `10.8.0.0/24`)을 유지하고 팀 통신용 서버를 별도로 준비했다.

| 항목 | 적용·확인 결과 |
| --- | --- |
| 전송 인터페이스 | Bridged NIC를 TRANSIT(em4)로 추가. DHCP 관찰 주소 `192.168.7.174/24`, 게이트웨이 `192.168.7.1`. 다음 실행 시 주소 재확인 필요 |
| 도달성 | TRANSIT의 B 발신 ICMP Echo request 허용 후 B→192.168.7.174 Ping 4/4 성공 |
| 서버 | `HAEDAM_TEAM_TRANSIT` / ovpns2, TRANSIT UDP 1195, 터널 `10.250.0.0/24` |
| 인증 | 팀용 CA·서버 인증서, 사용자별 인증서와 계정 준비. team-d·team-b-test 생성. 비밀값은 기록하지 않음 |
| 외부 허용 | B 시험·D 주소에서 TRANSIT address의 UDP 1195로 들어오는 규칙 준비. D 실제 접속은 내일 확인 |
| 터널 규칙 순서 | 팀 대역→10.250.0.1 ICMP Echo request 허용 → 팀 대역 기본 차단 → 기존 수업용 전체 허용 규칙 유지 |
| B 접속 | OpenVPN Connect의 team-b-test 접속 성공. pfSense 상태에 실제 주소 `192.168.3.4:61085`, 가상 주소 `10.250.0.2`, AES-256-GCM 확인 |
| 허용 시험 | VPN 발신 10.250.0.2에서 서버 10.250.0.1 Ping 4/4 성공 |
| 차단 확인 | TCP 443 접속 실패를 확인. 별도의 방화벽 화면에서 `HAEDAM_TEAM_VPN_DEFAULT_BLOCK`이 UDP 137을 차단한 로그 확인. 그 로그를 TCP 443 차단 증거로 간주하지 않음 |

team-d 프로필은 내일 D 본인 PC에서 확인할 예정이다. A·C 사용자·프로필은 아직 준비 전이다. 내부 서비스 경로를 푸시하지 않았고 inter-client 통신도 꺼져 있어, VPN 접속만으로 A→DB·A agent→C 연결이 완성된 것은 아니다.

### 문제와 해결

| 증상 | 확인·수정 | 결과 |
| --- | --- | --- |
| B에서 TRANSIT Ping 시간 초과 | 패킷 캡처에서 요청 도착을 확인. 규칙이 Echo reply로 되어 있어 Echo request로 수정 | Ping 4/4 성공 |
| 캡처가 빨리 끝남 | 게이트웨이 모니터 ICMP가 캡처 수를 빠르게 채우는 것을 확인. 캡처 수를 늘려 시험 요청 관찰 | B의 요청과 규칙 문제 구분 |
| D→B 임시 TCP 시험에서 방화벽 명령 권한 오류 | 관리자 PowerShell에서 한시적 출발지 제한 규칙·리스너로 재시험 | 연결 성공 후 임시 리스너·규칙 제거 확인. VPN 시험과 구분 |
| 다른 PC의 같은 VMnet 번호로 연결할 수 없는 분산 환경 | 팀 VPN 전송 구성을 준비하고 로컬 B 시험부터 수행 | 실제 다른 PC와 VM까지의 경로는 후속 확인 |
