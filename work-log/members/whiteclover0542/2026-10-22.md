## 문제와 해결

- 증상: GELF가 꺼져 있다고 잘못 판단해 Graylog 대조가 불가능하다고 안내했다.
- 원인: 어제 `.env` 상태(`GELF_ENABLED=0`)를 기준으로 말하고 오늘 바뀐 설정을 확인하지 않음.
- 재확인: `.env` 수정 시각(11:07:31) < 서비스 시작(11:07:48) < Kali 요청(11:13:43), 실행 중 프로세스 환경변수까지 확인한 뒤 대조 진행.

- 증상(14:40경): Windows에서 VM ssh가 비밀번호 창 전에 멈추고, VM 콘솔의 `check.sh`·`timedatectl`도 `org.freedesktop.timedate1 ... timed out`으로 멈춤.
- 원인: 자원(메모리·디스크·부하)은 정상이라 systemd/dbus 일시 무응답으로 추정. 재부팅 없이 14:48에 다시 응답. 근본 원인은 미확인.
- 함께 발견: 오전에 맞던 시계가 **동기화 풀림**(synchronized no) → timesyncd 재시작으로 복구(+6.9ms). 측정 직전마다 다시 확인.
- 증상: 1차 S7 파일을 접근 담당이 정해지기 전에 생성해 10분 창을 넘김. 해결: 폐기 후 **B 준비 확인 → 생성 → 즉시 접근** 순서로 재시험.
