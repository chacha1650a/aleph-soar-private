## 작성 방법

1. [공통 양식](../TEMPLATE.md)을 자기 폴더에 복사하고 파일명을 작업 날짜로 바꿉니다. 예: `work-log/members/whiteclover0542/2026-10-21.md`.
2. 목표, 실제 변경, 확인 방법·결과, 문제·해결, 미완료와 다음 첫 작업을 기록합니다. AI를 사용했으면 도구와 도움받은 범위도 적습니다.
3. PR·커밋과 비밀값을 제거한 증적 위치를 연결합니다. 설치·기동·연결·탐지·대응·원복 중 어디까지 확인했는지 구분합니다.
4. 자기 작업 브랜치에서 해당 일지를 커밋하고 PR로 공유합니다. 자세한 순서는 [저장소 협업 안내](../../CONTRIBUTING.md)를 따릅니다.

자기 일지는 본인이 관리합니다. 다른 사람의 일지나 확인하지 않은 결과를 대신 채우지 않습니다. 아직 기록하지 않은 날짜는 작성 완료로 표시하지 않습니다. 인덱스에 매일 링크를 추가할 의무는 없으며 GitHub에서 각 폴더를 열어 날짜별 파일을 확인할 수 있습니다.

기존 [개발 일지](../../docs/devlog/members/)와 [공통 작업·세션 인수인계](../README.md)는 과거 이력으로 유지합니다. 새 개인 일지는 이곳에 작성하고 같은 내용을 여러 곳에 복제하지 않습니다.

비밀번호·토큰·쿠키·인증서 개인 키·VPN 프로필·pfSense 설정 백업 원문·원문 개인정보는 올리지 않습니다. 캡처도 비밀값을 가린 뒤 연결합니다.
