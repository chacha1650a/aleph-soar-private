- D #80: 포털 HTTP 노드2개의 sendBody=true·JSON keypair ip 본문을 생성 원본에서 보존한다. 게시본 일치는 D 보고이며 이 통합에서 실제 n8n 엔진을 호출하지 않았다.
- D #71: 티켓 POST 본문 전송·via 보존·S7 파일 키 target을 유지한다.
- D #73: store_real(티켓 저장)과 dry_run(대상 조치)을 분리한다. 실제 저장+조치 없음은 detected 티켓만 만들고 가짜 applied 줄은 쓰지 않는다. 기존 호출에서 store_real 자체가 없는 경우만 dry_run=false를 실제 저장으로 해석한다.

충돌은 생성된 JSON을 한쪽 것으로 덮어 해결하지 않는다. 생성 원본을 합친 뒤 `python tools/build_n8n_workflows.py`의 정해진 순서로 다시 생성하고 `--check`로 재현성을 확인한다. 원복 자동화 live_release_enabled=false와 티켓 상태/소유권·기록 실패 시 중단 방어를 보존한다.

## 함께 보완한 연결

D의 target 단독/all-seats check는 `tickets` 목록을 반환한다. 기존 #67의 단일 자리 snapshot 검사로 이 목록을 검사하면 정상 응답도 보류되므로, 요청 scope에 맞게 목록을 검증한다. target 조회는 다른 자리·다른 group_key와 닫힌 채 활성 조치가 남은 과거 티켓도 보존한다. 누락/잘못된 목록은 성공한0건으로 만들지 않는다. 정확한 asset/via/action/target 기준의 `/active`와 원복 소유권 방어는 별도로 유지한다.

자리표시 저장소도 target/all-seats 조회를 같은 방향으로 지원한다. 모든 결과는 합성 상태이며 실제 C DB와 혼동하지 않는다. 기존 실제 저장 경로의 격리 검사/포털 리허설은 이제 store_real=true를 명시한다. 테스트를 통과시키려고 제품의 준비 기본값을 false→실제로 바꾸지 않는다.

## 버전·검사와 미검증

현재 후보의 파일 해시는 [10/30 소스 묶음](capstone/evidence/s1-candidate-20261030/versions.json)을 사용한다. 10/28·10/27 묶음은 그날의 근거로 그대로 보존했으며 `--packet`으로 조회한다. 기본 `check_s1_candidate.py`는 새 묶음을 읽고, 과거 home scope도 계속 읽되 어떤 scope에서도 runtime_verified/deployment_ready를 성공으로 만들지 않는다.

신규 연결 검사23개는 store_real/dry_run 조합8개, 준비 결과가 실제 C API에 detected만 남기는2개, 두 자리·닫힌 활성 소유권을 찾는 target 조회, 잘못된 목록 거부4개, 자리표시의 조회, S1의 명시적인 boolean 플래그6개·정상 출발지 보호1개다. 소스 묶음 검사·수집기 취소와 묶은50개 검사가 통과했다. 실제 C 엔진은 Flask test client+새 SQLite이며 Node Code 노드도 실제 n8n 엔진을 대신하지 않는다.

첫 전체 검사에서 수집 CLI의 Windows 시작이2.4초로2초 제한을 넘었다. 제한/중단 의미는 유지하고 해당 단위 검사의 정상 수집 결과만 먼저 준비해 취소 검사와 분리했다. 실제 CLI 병렬 검사는 따로 유지했다. 다음 전체 실행은530pass/1skip와 별도 D 수집기 exit2 실패1건이었다. 같은 고정 입력의 단독 실행·별도 병렬5회(총10수집)는 모두 통과했지만 당시 stderr가 버려져 원인을 확정하지 못했다. 병렬 테스트에 실제 자식 stderr 보존을 추가했으며 실패 로그를 삭제하지 않는다. 제품의 수집 제한·검증 조건은 완화하지 않았다.

## C/D가 확인할 항목

C는 DB·볼륨 백업을 먼저 하고 최종 main 배포 SHA를 받은 뒤에만 동일 버전으로 한 번 재빌드한다. 후보 커밋과 최종 main 병합 커밋을 구분한다. 재빌드한 이미지/DB 식별·코드 해시·실제 인증 조회/기록을 회신한다.

D는 같은 소스의 S1/haedam-10/11/12 원본과 게시본을 대조한다. 실제 저장/조치 플래그, 새 ticket_id/created, via·target 조회, 실패/종료/과거 ACK 뒤 대상 호출 중단, 수신 인증을 인수한다. 알림 템플릿의 condition_met_at 값은 A의 실제401 아홉 번째 시각과 별도로 대조하며, Graylog 이벤트 시각만으로 임계 충족 시각을 확정하지 않는다.

B는 최종 후보/검증 결과를 카드에 묶고 A/C/D 준비가 맞은 뒤 공동 시각을 예약한다. 첫 실제 S1은 포털 IP 차단 한 경로이고 pfSense 실제 차단·S7·S12 영향 시험과 겹치지 않는다. 승인 후 수동 해제·정상 로그인·재접근 증적까지 같은 시험 ID로 남긴다.
