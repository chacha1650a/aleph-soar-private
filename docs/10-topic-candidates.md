# 팀 투표용 프로젝트 후보 8개

기준: 4인·2주, 전원 Claude 사용·그중 2명 Codex도 사용. 공통 관심사는 계정 이상·자동 대응, 침해 흐름 관제, 권한·데이터 접근 추적입니다.

**아직 선택된 주제는 없습니다.** 아래는 비교를 위한 기획 제안이며 구현 가능성을 실증한 결과가 아닙니다. 인원별 역량·시간·장비와 평가 필수 요건을 확인한 뒤 범위를 조정합니다. 실제 데이터 대신 테스트 계정과 합성 자료를 사용합니다.

## A. 쇼핑몰 관리자 계정 보호

- **사용자·문제:** 작은 쇼핑몰의 운영자가 관리자 계정의 이상 로그인과 고객 자료 접근을 한 번에 보기 어렵다는 상황을 가정합니다.
- **시연:** 새 출발지 로그인 → 예상 밖 관리자 권한 변경 → 합성 고객 자료 반복 조회 → 사건 생성 → 테스트 계정 접근 제한·해제.
- **MVP 3개:** 관리자 로그인·역할, 자료 조회 이벤트와 타임라인, 탐지·대응·원복 기록.
- **범위 경계:** 상품 몇 개와 합성 고객 자료 화면만 둡니다. 결제·배송·주문 처리 시스템은 제외합니다.
- **첫 확인 과제:** 정상 관리자 업무와 의심 입력을 구분할 테스트 정책을 정합니다.

## B. 사내 문서 접근·반출 징후 추적

- **사용자·문제:** 사내 보안 담당자가 권한 변경 뒤 어떤 문서를 얼마나 열람·다운로드했는지 추적하는 상황입니다.
- **시연:** 문서 열람 역할 변경 → 제한 문서 접근 또는 반복 다운로드 → 근거가 연결된 사건 → 테스트 접근 권한 제한·복원.
- **MVP 3개:** 문서 2종의 접근 정책, 사용자·문서별 감사 타임라인, 정상·의심 접근 비교와 대응.
- **범위 경계:** 앱에서 제공하는 합성 문서의 접근을 기록합니다. 실제 PC 전체 파일 감시나 외부 전송 차단은 제외합니다. 다운로드 로그만으로 외부 유출이 확인됐다고 표시하지 않습니다.
- **첫 확인 과제:** 자료 민감도·직무 권한·허용된 반복 조회를 어떻게 표현할지 정합니다.

## C. 제조업 협력사 포털 관제

- **사용자·문제:** 제조사 관리자가 협력사별로 발주·생산 자료의 조회 범위를 관리하는 상황입니다.
- **시연:** 협력사 계정의 이상 로그인 → 권한 변경 → 다른 협력사 자료 조회 시도 → 정책 위반 로그·사건 → 테스트 계정 제한·해제.
- **MVP 3개:** 협력사 2곳·역할 2종, 발주·생산 자료 접근 이벤트, 여러 로그를 연결한 사건·대응.
- **범위 경계:** 실제 생산 설비와 공장 제어는 다루지 않습니다. 조회가 거부된 시도와 실제 성공한 접근을 구분합니다.
- **첫 확인 과제:** 조직·계정·자료의 소유 관계를 계약에 표현하고 다른 조직의 정상 사건이 섞이지 않게 합니다.

## D. API 키·서비스 계정 오남용 감시

- **사용자·문제:** 서비스 운영자가 자동화 프로그램이 사용하는 키의 사용 범위와 이상 호출을 확인하는 상황입니다.
- **시연:** 테스트 키의 호출 증가 → 허용되지 않은 자원 요청 → 같은 키의 흐름으로 사건 생성 → 키 사용 중지·교체 확인.
- **MVP 3개:** 로컬 테스트 API와 키별 범위, 키 ID·자원·결과 기반 탐지, 중지·교체와 이력 화면.
- **범위 경계:** 실제 외부 서비스 키는 사용하지 않습니다. 로그에는 원문 키 대신 식별자만 남깁니다. 폐기한 키를 복원하는 대신 새 키로 정상 이용을 재개하는 흐름입니다.
- **첫 확인 과제:** 정상 배치 작업의 호출 증가와 오남용 정책 위반을 구분합니다.

## E. 클라우드 계정·권한 이상 관제

- **사용자·문제:** 클라우드 운영자가 로그인, IAM 권한 변경, 저장소 접근을 같은 주체의 사건으로 이해하는 상황입니다.
- **시연:** CloudTrail 형식의 테스트 로그인 → 권한 변경 → 저장소 객체 접근 로그 재생 → 타임라인·근거 → 대응안과 로컬 테스트 대상 상태 변화.
- **MVP 3개:** 선택한 이벤트 유형의 로그 정규화, 계정·자원·시간 기반 사건 연결, 사건 화면과 테스트 대응 이력.
- **범위 경계:** 먼저 샘플 로그와 로컬 대응으로 검증합니다. 실제 AWS 계정 수집·권한 변경은 별도 연동 단계입니다. 이를 완료한 것처럼 표시하지 않습니다.
- **첫 확인 과제:** 실제 연동을 선택하면 관리 이벤트와 객체 접근 데이터 이벤트의 수집 범위·권한·과금 조건부터 확인합니다. 이 후보는 외부 환경을 연결할 때 추가 준비가 필요합니다.

## F. 개발팀 운영 변경 감사

- **사용자·문제:** 개발팀이 계정 권한 변화와 운영 변경 요청이 승인된 작업인지 확인하는 상황입니다.
- **시연:** 개발자 역할 변경 → 승인 기록 없는 테스트 배포 요청 → 정책 위반 탐지 → 요청 거부·사건 기록 → 승인된 정상 요청과 비교.
- **MVP 3개:** 로컬 운영 콘솔, 승인·권한·요청 이력 연결, 정책 위반 사건과 정상 복구 흐름.
- **범위 경계:** 실제 서버 배포·GitHub 조직 설정·운영 비밀 변경은 제외합니다. 모의 운영 콘솔의 요청을 평가합니다.
- **첫 확인 과제:** 승인 주체·대상·유효 시간과 실제 요청의 연결 기준을 정합니다.

## G. 자동 대응·원복 검증 랩

- **사용자·문제:** 보안 담당자가 자동 대응의 중복 실행·부분 실패·해제 결과를 검증하는 상황입니다.
- **시연:** 계정 이상 경보 입력 → 테스트 계정 잠금 → 같은 경보 재입력 → 일부 단계 실패 재현 → 재시도·원복 결과 확인.
- **MVP 3개:** 계정 로그 기반 경보 1종, 대응·실패·재시도 흐름, 사전·사후 상태와 원복 이력 화면.
- **범위 경계:** 대응 대상은 로컬 테스트 API입니다. 지원할 조치 수를 작게 정하고 상태 복구를 검증합니다. 광범위한 공격 탐지나 외부 장비 연동은 확장 후보입니다.
- **첫 확인 과제:** 작업 식별자·중복 방지·부분 실패 시 복구 기준을 정합니다.

## H. 보안관제 사건 재생·훈련 도구

- **사용자·문제:** 교육생과 보안 입문자가 동일한 로그로 사건 분석과 대응 판단을 반복 연습하는 상황입니다.
- **시연:** 정상/의심 시나리오 선택 → 인증·권한·자료 접근 로그 재생 → 타임라인 관찰 → 대응 선택 → 기대 결과와 실제 결과 비교.
- **MVP 3개:** 라벨이 있는 시나리오 3종 재생, 사건·근거 화면, 테스트 대응 결과와 학습 피드백.
- **범위 경계:** 합성 이벤트를 재생하며 외부 시스템에 공격을 실행하지 않습니다. 정답은 설계한 테스트 정책의 기대값이고 실제 침해의 보편적 정답이라고 주장하지 않습니다.
- **첫 확인 과제:** 정상 대조와 의심 사건의 기대 결과가 모호하지 않게 입력·정책·대응 결과를 설계합니다.

## 공통 뼈대 활용

현재 Flask 시작 앱, 역할·스킬, 작업 지시서, 계약 검사와 CI는 어느 후보에도 출발점으로 활용할 수 있습니다. 이벤트·사건 계약과 작업 DAG는 초안이므로 후보에 맞춰 P01에서 수정합니다. API 키 ID, 협력사 조직, 문서 식별자, 승인 기록 등을 현재 계약이 이미 지원한다고 가정하지 않습니다.

선택한 후보에서는 수집 → 사건 연결 → 근거 표시 → 테스트 대응·복구 중 핵심 경로를 먼저 통합합니다. 평가에서 4계층이 필수인지, 필요한 환경과 담당 역량이 확보됐는지를 확인해 확장 범위를 정합니다.

## 팀원 투표 양식

```text
이름:
1순위 후보 ID:
2순위 후보 ID:
선택 이유 한 줄:
맡아보고 싶은 작업:
가장 걱정되는 부분 / 필요한 도움:
```

각자 먼저 작성한 뒤 상위 후보 2개를 비교합니다. 단순 선호와 실제 담당 가능성을 함께 보고, 불확실한 연결 1개를 짧게 확인한 뒤 최종 선택합니다. 받은 답변은 [팀원 의견 기록](11-team-feedback.md)에 모읍니다.

## 팀 채팅에 공유할 문구

> 프로젝트 주제를 고르려고 후보 8개를 정리했습니다. 공통 방향은 계정 이상·침해 흐름·권한과 자료 접근 관제입니다. 후보 문서를 읽고 1·2순위, 이유 한 줄, 맡고 싶은 작업을 적어주세요. 4인·2주에 맞춰 상위 후보를 좁힌 뒤 MVP를 정하려고 합니다. 아직 확정된 주제는 없습니다.

## 참고와 제안의 구분

후보와 MVP 범위는 이번 팀 논의를 위한 기획 제안입니다. 계정 악용의 위협 배경은 [MITRE ATT&CK Valid Accounts](https://attack.mitre.org/techniques/T1078/)를 참고했습니다. E의 실제 AWS 연동 범위는 [CloudTrail 관리 이벤트](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-management-events-with-cloudtrail.html)와 [데이터 이벤트](https://docs.aws.amazon.com/awscloudtrail/latest/userguide/logging-data-events-with-cloudtrail.html)를 기준으로 별도 확인합니다. 이 자료들이 제안한 MVP의 완주 가능성이나 팀 역량을 검증한 것은 아닙니다.
