# 기획서 합의본 — S7 관련 부분 점검

- 작성: shk12170-dev · 2026-10-19 · 대상: [기획서 합의본](../../team_docs/기획서_합의본.md)(②③④⑤), 비교: [기획서 초안](../../team_docs/기획서.md), [시나리오 목록](../03-scenarios.md)
- 상태: 제안. **합의본 파일은 수정하지 않았습니다.** 10/21 팀원 확인 마감 전에 myeongjundev(작성자)에게 전달할 의견입니다.
- 읽은 범위: 합의본 전체, 초안과 시나리오 목록의 S7 해당 줄. 수업 원본 자료와 S1~S10 가이드 PDF는 대조하지 않았습니다.

## 1. 요약

합의본 ⑤는 케이스에 관계없이 쓰는 절차라 S7에도 대부분 적용됩니다. 다만 S7은 **차단이 아니라 티켓 + 파일 복구**가 대응이라, 현재 틀에서는 효과·원복 판정이 비어 있습니다. 해결할 것 6건, 확인할 것 3건입니다.

## 2. 해결할 것

### 2-1. 대응 유형에 "복구"가 없다 (⑤ 5.2, 5.4, 5.5) — 우선순위 높음
- 현재 유형: 자동 차단 / 통지·티켓 / 사람 승인. S7(114 티켓 + 변조 파일 원본 복구)은 가장 가까운 "통지·티켓"에 넣으면 효과 확인·원복 지표가 `N/A(차단 없음)`이 됩니다.
- 그러면 공지의 "자동 대응 원복 절차"와 "정상 동작 확인" 장면을 S7에서 측정하지 못합니다. 파일을 복구했는지는 해시 비교로 객관적으로 확인할 수 있는데 지표에서 빠집니다.
- 제안: 5.2 대응 유형 표에 한 줄 추가.

| 대응 유형 | 예 | 5단계 통과 기준 | 효과 확인·원복 지표 |
| --- | --- | --- | --- |
| 자동 복구 | S7 변조 파일 원본 복구 | 티켓 1건 생성, 변조 파일이 기준본으로 교체됨 | 측정 (5.4 파일 복구 행) |

- 5.4에 행 추가: `파일 복구 | 변조 경로를 다시 요청 → 변조 전 내용으로 응답 | 해당 파일의 해시가 기준본 해시와 같음, FIM이 복구 변경을 재탐지하지만 사건을 중복 생성하지 않음`

### 2-2. 복구 변경이 FIM에 다시 잡힌다 (⑤ 5.2 6단계 중복 확인)
- 복구도 파일 변경이라 Wazuh가 다시 알립니다. 복구 알림이 새 사건으로 번지면 6단계(중복 확인)가 실패하거나 무한 반복될 수 있습니다.
- 제안: 복구 직후 일정 시간 같은 경로의 FIM 알림을 "복구 확인"으로 처리하는 규칙을 ④에 명시. 시험 항목에도 추가.

### 2-3. 묶기 키가 ④에 없다 (④)
- 초안의 "FIM 묶기 키: 파일 경로로 FIM과 웹 접근 연결"([초안](../../team_docs/기획서.md) 미결 표)이 합의본 ④에는 S12 묶기 키만 언급되어 있습니다. [시나리오 목록](../03-scenarios.md)도 S7을 "원본은 묶기 없음"이라 적고 전역 집계 위험을 경고합니다.
- 제안: ④에 "S7은 자산 + 웹 루트 기준 상대 경로로 묶는다"를 추가. 계약안은 [README](README.md).

### 2-4. S7 입력표가 필요하다 (⑤ 5.2 경계 입력)
5.2는 "케이스마다 입력표를 만든다"고 했으므로 S7 안을 제안합니다.

| 입력 | S7 내용 | 기대 |
| --- | --- | --- |
| 정상 | 허용된 배포 절차로 파일 교체, 이후 정상 접근 | 미발동 (허용 변경 처리) |
| 조건 일부만 충족 | 파일만 생성/변경, 웹 접근 없음 | FIM 알림만, 사건 미발동 |
| 조건 일부만 충족 | 웹 접근만, 파일 변경 없음 | 미발동 |
| 경계 바로 아래 | 신호 종류 1개 (`card(signal_kind)=1`) | 미발동 |
| 전체 조건 충족 | 같은 경로에서 파일 생성 후 10분 안에 웹 접근 | 발동 1건 |
| 시간 창 밖 | 생성 후 10분을 넘겨 접근 | 미발동 |
| 순서 반대 | 접근(404) 뒤 파일 생성 | 순서를 요구하기로 정하면 미발동 (⑤ 5.9 항목) |
| 혼합 | 파일 A 생성, 파일 B 접근 | 경로별로 따로 판정, 미발동 |

### 2-5. 사전 시험(5.10)에 S7이 없다
- S1·S4·S12·S11만 있습니다. S7은 구현 전에 아래를 확인해야 합니다.
  - Wazuh FIM이 **실시간 감시** 설정에서 몇 초 안에 알리는가 (기본 주기 검사는 간격이 길어 MTTD 목표를 못 맞출 수 있음 — 실제 값은 설치 후 측정 필요)
  - 포털을 Docker로 올릴 때 웹 디렉터리를 호스트의 Wazuh 에이전트가 감시할 수 있는가(볼륨 마운트, 에이전트를 컨테이너 안에 둘지)
  - 변조 파일을 실제로 기준본으로 되돌릴 수단(n8n에서 호출 가능한 경로)
- 제안: 5.10에 S7 줄 추가.

### 2-6. 측정 시각 정의 (⑤ 5.5)
- "조건 충족 시각"은 두 신호 중 **나중 신호(웹 접근)** 의 원본 시각입니다. 이를 S7 정의로 명시합니다. 첫 공격 시각은 파일 생성 시각으로 따로 보존합니다.
- 반복 시험 초기화(5.3)의 "시험 주체"에 계정·IP 외에 **파일 경로**를 추가합니다(경로가 묶기 키이므로 `run_id`별로 다른 경로 사용).

## 3. 확인할 것

1. **대응 봇 번호:** 초안은 S7을 "114 티켓 + 변조 파일 원본 복구"로 적었지만 복구 봇은 번호가 없습니다(108·111~114는 원본, 115·116은 VPN 회수·서비스 회복으로 제안됨). 복구용 번호를 새로 둘지 정해야 합니다.
2. **필수 4종 중 자동 차단 하나 이상(5.1):** S7은 차단형이 아닙니다. S8·S10(IP 차단) 또는 S12가 자리 B·D에 있으면 충족되지만, 자리 확정 뒤 다시 확인합니다.
3. **정상 변경의 허용 방식:** 관리자의 정상 배포를 FIM이 오탐하지 않게 하는 방법(배포 시간대, 배포 계정, 해시 목록)을 정해야 합니다. ⑤ 오탐 지표(정상 업무 T분)와 직결됩니다.

## 4. 합의본 ② ③ 관련 (10/20 이후 작성 예정 부분)
