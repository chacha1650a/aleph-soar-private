## 수정 필요

1. **정상 배포의 허용 방식이 없음**
   - 근거: 합의본에 "배포" 관련 서술이 없고, 오탐 지표(L527, 정상 업무 T분)만 있음. 관리자의 정상 파일 교체를 FIM이 변조로 볼 수 있음.
   - 제안: ⑤ 입력표(S7)에 "정상 배포" 입력을 넣고, 허용 방식을 정함(예: 배포 계정, 배포 시간대, 배포 전용 경로 제외, 해시 목록 갱신 절차).
2. **원본 보관 위치·권한이 문서에 없음**
   - 근거: L339는 "원본으로 복구(해시 대조)"만 적음. 원본을 어디에 어떤 권한으로 두는지 없음.
   - 제안: ③ 117 설명에 "원본은 감시 디렉터리 밖, 웹 계정이 쓸 수 없는 읽기 전용 위치"를 명시. 웹 계정이 원본까지 바꾸면 복구가 무의미해짐.
3. **복구 수단이 두 안으로 열려 있음**
   - 근거: L605 "Wazuh API로 실행하는 active response 또는 포털 API".
   - 제안: Wazuh active response로 정하고 n8n은 Wazuh API로 호출. 포털 API 방식은 포털이 침해됐을 때 복구 수단도 영향을 받을 수 있음. 근거와 안은 `team_docs/작업방향-S7-shk12170-dev.md` 8-2절(PR #14).
4. **파일 키에 `asset_id` 포함 여부**
   - 근거: L390, L405. 자산이 하나인 동안은 충돌 없음. 교차 검토 PDF 04번도 같은 지적.
   - 제안: 제출본에 "자산이 늘면 `asset_id` + 상대 경로를 키로 쓴다" 한 줄 추가. 계약안은 이미 그렇게 제안(`docs/s7-draft/README.md`).
5. **사건 계약에 `username` 없는 사건 반영**
   - 근거: L358은 계획만 있음. 현재 `contracts/incident.schema.json`은 `username` 필수.
   - 제안: S7 필요분을 `docs/s7-draft/`에 만들어 둠(채택은 조율 후). A·D의 요구와 합쳐 한 번에 변경.
