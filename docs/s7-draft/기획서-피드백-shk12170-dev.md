## 2. 보완해야 할 점

### 2-1. PDF가 남은 것으로 지적한 항목

1. **S4·S8 순서 조건:** "실패 뒤 성공", "스캔 뒤 실패"를 순서까지 요구할지 5.9에서 미정. 도구가 순서를 판정할 수 있는지도 확인 필요. 역순·창 밖·한 종류 누락 시험을 명시해야 함
2. **pfSense 기존 연결·관리 예외:** state 삭제는 적었으나 anti-lockout, 규칙 우선순위, 관리망 예외는 미명시
3. **티켓 중복·재시도:** 같은 계정의 서로 다른 IP가 한 티켓에 묶일 때 대상별 차단이 빠지지 않는지, 재전송·실패 후 재시도·동시 실행에서 중복 조치가 없는지 확인 필요
4. **S12 지표:** MTTD가 Graylog 후보 이벤트 시각을 종점으로 쓰지만 최종 판정은 n8n이 함. 후보 생성·최종 판정·조치 완료·회복 확인 시각을 구분하고 임계값·제한 시간을 수치로 확정
5. **사전 시험 통과 기준:** 16GB PC 동시 구동의 OOM·로그 유실·회복 지연 합격선, "n8n IP 차단 1회"에 필요한 최소 API와 담당 지정
6. **제출본 내부 표시:** 메모·초안·팀 확인·가칭 표시 정리(10/22)

### 2-2. 문서를 읽고 추가한 의견

- **사전 위험 시험이 아직 0건 실행입니다.** 가장 큰 위험은 관제 PC 메모리(WSL 10~11GB에 Graylog + Wazuh 전체)입니다. 제출 전에 `docker stats` 실측값이라도 넣으면 계획값이 근거 있는 수치가 됩니다.
- **MVP가 S1이라 나머지 케이스는 10/28 판단에 달려 있습니다.** 각 자리의 사전 시험(S7 realtime 경보·마운트 감시·복구 수단 등)이 같은 기간 안에 끝나도록 일정을 확보해야 합니다.
- **S7 복구 수단이 두 안으로 열려 있습니다.** (Wazuh active response 또는 포털 API, L605) 포털이 침해되면 복구 수단도 영향받을 수 있으므로 Wazuh active response를 제안합니다.
- **S7 원본 보관 위치·권한이 없습니다.** 감시 디렉터리 밖, 웹 계정이 쓸 수 없는 읽기 전용 위치를 명시해야 합니다.
- **정상 배포 처리가 없습니다.** 관리자의 정상 파일 교체 시 오탐 처리 방식을 정해야 오탐 지표를 측정할 수 있습니다.
- **파일 키의 `asset_id` 포함 여부**를 한 줄로 정해야 합니다.
