# 망 허용표 확장 · S1~S10 연결과 허용·거부 시험

기준일: 2026-10-16 (Asia/Seoul) · 작성: Claude · 상태: 검토용 초안 · 미적용·미시험 · 팀 합의 전

## 1. 목적과 경계

[R08 3절의 허용표 초안](21-telecom-portal-defense-plan.md#3-4계층의-정의와-실제-통신-경로)을 줄 단위 규칙으로 나누고, 각 줄에 로그 위치·그 줄을 쓰는 참고 시나리오 [S1~S10](03-scenarios.md)·허용 시험·거부 시험을 붙였다. "망을 잘 설계했다"를 S1~S10의 관측과 차단을 망이 받쳐 주는지, 그리고 실제 연결과 로그로 보여 줄 수 있는지로 판단하기 위한 자료다.

- 기존 문서는 바꾸지 않았다. 이 문서의 규칙·포트·주소는 적용하지 않은 설계 예시다.
- 각 시험은 [G1-NET](22-p01-access-and-g1-preflight.md#3-g1-시험-카드)의 세부 시험이다. DB·WAF·로그 관련 줄은 G1-DB·G1-WAF·G1-LOG와 함께 수행한다.
- S1~S10은 참고 자료 167·168의 정의이며 팀의 구현·검증 결과가 아니다.

## 3. 설계 원칙

1. **출발지 IP 보존:** S3·S5·S6·S8·S10이 IP로 묶거나 IP 개수를 센다. 외부와 DMZ 사이에 출발지를 바꾸는 NAT를 두지 않는다. WAF가 `X-Forwarded-For`를 덮어쓰고 앱은 WAF만 신뢰한다. 공방전 진입이 공용 NAT·VPN으로 한 주소에 합쳐지면 이 다섯 규칙과 IP 차단을 다시 설계한다.
2. **차단 지점의 로그:** IP 차단(대응 112)을 실행하는 장비의 거부 기록이 S5의 입력이다. 차단은 했지만 기록이 없으면 S5가 성립하지 않는다.
3. **구역별 외부 송신 기본 거부:** DMZ·앱·DB에서 외부로 나가는 신규 연결을 막고 기록한다. S7과 정보 반출 시도가 경계 로그로 남는다.
4. **관리 경로 분리:** 관리 화면·내부 대응 API·로그 입력 포트는 관리 구역에서만 닿게 한다. 외부에서 로그 입력 포트에 닿으면 가짜 로그를 주입할 수 있다.
5. **시간 일치:** S1~S10은 5~30분 시간창을 쓰고, S4는 순서, S2는 심야 기준이 필요하다. 관리 구역에서 NTP를 제공하고 로그에 발생 시각과 수신 시각을 함께 남긴다.

## 5. 줄별 허용·거부 시험

공통 규칙은 다음과 같다.

- 거부 시험은 허용 규칙을 바꾼 뒤 **새 연결**로 확인한다. 기존 연결은 대상 state만 회수하는 별도 시험으로 둔다. 전체 state 초기화로 정상 B 연결까지 끊지 않는다([docs/21 3절](21-telecom-portal-defense-plan.md#3-4계층의-정의와-실제-통신-경로)).
- 정상 B 생성기를 같은 시간에 돌려 오차단을 함께 센다.
- 응답도 로그도 없으면 "거부"가 아니라 "미관측"이다. 경로와 센서를 먼저 진단한다.
- 입력은 랩 안의 합성 요청만 쓴다. 표식 문자열로 원본과 중앙 수신을 대조한다(G1-LOG).

## 7. 배치 B를 고를 때 달라지는 점

docs/21의 배치 B는 WAF와 앱을 한 VM에 둔다. 이 경우 NR-04·NR-05는 pfSense를 지나지 않으므로 호스트 방화벽 시험으로 바꾸고, WAF–앱 망 경계는 검증 범위에서 빠졌다고 기록한다. NR-06(앱→DB)은 pfSense 경유로 유지한다.

## 8. 미정·확인 필요

1. 공방전 진입 경로: 팀별 고유 IP가 유지되는지, VPN이 주소를 변환하는지. NR-21과 IP 기반 규칙 다섯 개가 이 답에 달려 있다.
2. IP 차단 지점: pfSense 차단 목록과 WAF 거부 목록 중 무엇을 쓸지, n8n이 그 목록을 바꾸는 방법(NR-15)은 미확인이다.
3. 관리자·운영자 기능의 노출 위치: S6의 성립 방식을 정한다.
4. S7 포함 여부: 업로드 기능을 추가할지, 보류할지.
5. 제품·포트: Graylog input 종류, 파일 전달기, 앱·내부 대응 API 포트, HTTPS 인증서.
6. DB 시험 호스트 위치, 배치 A/B, 실제 장비와 기간.
