# 통신 배경 전환안의 Codex 검토 요청 · R07

기준일: 2026-10-16 (Asia/Seoul) · 작성: Claude 제안 · 상태: Codex 검토 요청 · 팀 채택 전

사용자는 SK aleph 보안 네트워크 과정의 파이널 팀 프로젝트로 **통신 분야**를 제안하고 싶어 합니다. Claude는 통신망 자체를 재현하지 않고 **통신사 운영망의 외주·장비 원격접속 통제**로 범위를 정하는 안을 추천했습니다. 사용자가 이 안을 Codex에게 검토받기로 했습니다. 아래는 검토 대상 원안이며 팀 채택이나 기존 결정의 변경을 뜻하지 않습니다.

## 1. 배경과 전제

- 4인·2주(저장소 기준). 사용자는 "3개월 과정의 파이널 팀 프로젝트"라고 설명했으며, 프로젝트 기간이 2주인지는 확인이 필요합니다.
- 사용 예정 도구: Wazuh, Graylog, pfSense, n8n, Kali Linux, Docker. 이후 다른 팀과 공방전 예정이며 규칙은 미정입니다.
- 앞선 배경 후보: 스마트팩토리([R05 1안](18-security-network-career-direction.md)), 금융([R06](19-finance-background-review.md), Codex 판정: 범위를 좁힌 전환 권고). 어느 것도 팀 채택 전입니다.
- 이 안은 R06과 뼈대가 같습니다. 외부 업체 계정 탈취, 망 경계, 승인된 접속 회수, 차단 효과 재시험, 정상 업무 유지, 안전한 복귀입니다. R06에서 Codex가 지적한 P1 수정(조치 대상 네 가지 분리, VPN 주체 연결, 인증 방식 고정, 작업 ID 기반 정상 업무 지표, DMZ 고객 서비스 제외)을 전제로 합니다.
- 사용자가 들은 SK 측 관계자의 민관 협력 업무와 연결될 가능성이 있으나, 그 업무의 내용은 확인하지 않았습니다.

## 2. 추천 이유 (Claude 판단과 근거)

1. **과정 이름과의 연결:** "보안 네트워크" 과정에서 통신사 네트워크 보안은 설명이 필요 없는 주제라는 판단입니다.
2. **최근 사고가 네트워크 보안 문제입니다.** SKT는 서버 28대에서 BPFDoor 27종 등 악성코드 33종이 확인됐고 IMSI 2,696만 건이 유출됐으며, 로그가 없는 기간은 유출 여부를 확인하지 못했고 24시간 내 신고를 지키지 않았습니다.[T01] KT는 모든 펨토셀이 같은 제조사 인증서를 써서 복제 장비가 내부망 인증을 통과했고, 웹셸·BPFDoor를 2024-03 발견하고도 신고하지 않았습니다.[T02]
3. **민관 협력이 늘고 있습니다.** SKT 사고 뒤 통신 분야 주요정보통신기반시설 지정 범위가 네트워크 장비에서 서버·관리망으로 넓어졌고, 가입자 인증 서버(HSS)가 새로 포함됐습니다.[T03] 2025-10-22 범부처 정보보호 종합대책은 공공·금융·통신 IT 시스템 약 1,600개 점검과 통신사 불시 점검을 담았습니다.[T04] 국정원 판교캠퍼스에서는 국가·공공기관과 보안 기업이 위협 정보를 공유합니다.[T05]
4. **진입 경로:** SKT 정보보호 인력 219.2명 중 168.1명이 외주라, 통신사 일을 하는 관제·보안 기업을 통한 진입이 넓다는 판단입니다.[T06]

### 민관 협력 층 (2주 범위 후보)

- **침해사고 신고 보고서:** 탐지 시각부터 24시간 신고 시한까지의 타임라인을 맞춘 보고서 양식.
- **위협 정보 공유:** 공격 IP·시각·수법을 다른 기관에 넘길 수 있는 목록 형식으로 내보내기.
- **기반시설 점검 체크리스트:** 가입자 정보 서버·관리망에 대한 점검 항목 일부를 직접 점검하고 결과 기록.

### 선택 확장

- Open5GS(오픈소스 5G 코어)와 UERANSIM(단말·기지국 시뮬레이터)을 Docker로 띄워 코어망 구성 요소를 보여 주는 방안. 일반 지식 기준이며 설치·호환성은 시험하지 않았습니다. 2주 핵심 흐름에는 넣지 않는 것을 전제로 합니다.

### 주의할 점

- SK 과정에서 SKT 사고를 다룰 때는 특정 회사의 잘못이 아니라 "업계가 겪은 사고 유형을 실습으로 검증했다"는 표현을 씁니다. 과정 측의 허용 범위는 강사 확인이 필요합니다.
- 실제 통신망·가입자 정보·사업자 시스템과 연결하지 않습니다. 가입자 정보는 합성 데이터입니다.

## 4. Codex에게 요청하는 검토

1. 통신 / 금융 / 스마트팩토리 중 무엇이 이 과정의 파이널 프로젝트에 맞는지 판단해 주세요. 결론은 통신 전환 / 금융 전환 / 판단 보류로 주세요.
2. 2절의 통신 규제 근거를 공식 출처로 확인해 주세요. 정보통신망법의 침해사고 신고 조문과 시한, 정보통신기반보호법의 기반시설 지정·취약점 분석 조문, 2025-08 통신 분야 지정 확대와 2025-10-22 범부처 종합대책의 정부 원문입니다. 쓸 수 있는 범위와 과장 위험을 짚어 주세요.
3. S4와 T1의 현실성과 2주 구현성을 검토해 주세요. ATT&CK 매핑은 T1133, T1078, T1046에 더해 T1205(Traffic Signaling), T1070(Indicator Removal) 같은 후보가 맞는지 확인해 주세요. Claude는 이 후보를 검증하지 않았습니다.
4. 민관 협력 층 세 가지가 2주 범위와 평가에 맞는지, 실제 신고 양식이나 위협 정보 공유 표준(예: STIX)을 써야 하는지, 단순화한다면 어떻게 표시해야 하는지 검토해 주세요.
5. Open5GS·UERANSIM 선택 확장의 타당성, 필요한 자원, 공방전과의 관계를 판단해 주세요.
6. SK 과정에서 SKT·KT 사고를 다루는 표현의 기준을 제안해 주세요.
7. R06 Codex 지적 중 통신안에 그대로 적용되는 것과 새로 필요한 수정을 정리하고, 한 문장 주제와 최소 시연 흐름을 제안해 주세요.
