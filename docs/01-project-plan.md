# 프로젝트 기획 초안

상태: 팀 검토 전 · 기준일: 2026-10-15 (KST)

## 문제와 목표

공장 생산망과 본사 관리망에서 발생한 보안 이벤트가 따로 남으면 하나의 침해 흐름을 파악하기 어렵습니다. 계층별 신호를 같은 사건으로 연결하고, 대응 결과와 원복까지 확인할 수 있는 실습 환경을 기획합니다.

참고 시나리오는 가상의 제조사 ‘한빛정밀’이며, 실제 적용할 서비스명과 사용자 설정은 미정입니다.

## MVP 제안 — 팀 합의 필요

1. Flask의 인증 이벤트를 Graylog에서 검색한다.
2. S1(저속 브루트포스), S4(실패와 성공의 결합)를 우선 검증한다.
3. n8n으로 계정 잠금과 티켓 생성을 연결하고, 해제 절차를 확인한다.
4. 동일 입력의 중복 대응 방지와 정상 사용자 오탐 사례를 확인한다.

이 MVP는 앱 계층의 첫 통합을 위한 제안입니다. 참고안의 4계층 통합 목표와 구분하며, 주제 논의와 과제 필수 요건 확인을 거쳐 범위를 확정합니다. 다른 주제를 선택하면 이 기획도 결정에 맞춰 수정합니다.

## 확장 후보

- pfSense 경계 로그와 앱 신호 상관: S8, S10
- Wazuh 파일 변경 신호 연계: S7
- 앱 권한 이벤트와 MySQL 감사 신호 연결: S9 확장
- Cloudflare WAF 샘플 연계와 하나의 인시던트로 취합
- S2, S3, S5, S6를 포함한 전체 S1~S10 회귀 검증

## 완료 기준 초안

| 항목 | 확인 방법 |
| --- | --- |
| 수집 | 입력한 테스트 이벤트를 필수 필드와 함께 검색 가능 |
| 탐지 | 정상·임계 미만·임계 충족·서로 다른 사용자/IP를 구분 |
| 대응 | 테스트 대상의 상태 변화와 티켓 생성 확인 |
| 원복 | 차단 해제·계정 해제·기존 상태 복원 확인 |
| 재현 | 다른 팀원이 문서를 따라 동일 결과 재현 |
| 증적 | 실행 시각, 입력 조건, 로그, 티켓, 원복 결과를 연결 |

성능 수치와 마감일은 아직 정하지 않았습니다. 원본의 측정 수치를 팀의 목표나 결과로 사용하지 않습니다.
