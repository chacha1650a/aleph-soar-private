# S1-after-03 (보강 후 3회차 · r2 + 같은 계정 정상 출발지, GELF TCP) — 현장 기록표

> **재예약 회차.** 10/29에 계획했으나 R1(S1-after-02)에서 포털 GELF UDP 유실(원본 10건/수신 9건, 9번째 = 조건 충족 신호)이 나와 미실행(B 결정 15:3x). 포털 GELF TCP(backend #8 `f3faa1c`)를 10/30 배포했고 11/02 TCP 12201 `ESTAB`·`web.*` 원본=수신(S12 OBS01 453/453, S8·S10 각 5/5)을 확인했다. B 결정대로 **새 backend SHA·계정·출발지**로 진행한다. 10/29 계획값(`.15`·`zz_s1_1029_r2`)은 쓰지 않는다.

> 시험 중에는 빈칸만 채운다. 시각은 **포털 VM·Graylog·n8n 기록 기준**(사람이 본 시각은 "(관찰)"). 비밀번호·`X-Response-Key`·세션 값은 적지 않는다.
> S1-after-02와 같은 흐름에 **같은 계정의 정상 출발지 로그인**을 더하고, 이번에는 **로그인 로그(`login-*`·`username`) TCP 수신을 원본과 event_id로 대조**한다. 경계 8회 [S1-edge-01](../S1-edge-01/README.md)과 같은 시각에 시작하지만 계정·출발지가 달라 Graylog 키·티켓이 따로 생긴다.
