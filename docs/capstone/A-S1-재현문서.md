# S1 재현 문서 (저속 브루트포스 → 출발지 자동 차단)

- 담당: whiteclover0542(A) · 작성 2026-11-02 · 상태: 실측 2회(S1-after-01 10/28·S1-after-02 10/29) 기준. 다른 팀원이 **문서만 보고** 같은 결과를 내도록 전제·절차·판정 기준을 한 곳에 모은다.

- 안전: 격리 랩 전용. `zz_` 시험 계정과 문서용 대역(공격 `203.0.113.11~19`, 정상 `203.0.113.100~109`·`.12`)만. 시도 비밀번호·토큰·세션 값은 로그·캡처·문서에 남기지 않는다.

## 1. 기대 결과 (이게 나오면 재현 성공)

같은 `username`+`src_ip`로 로그인 실패가 30분 안에 9건 이상이면:
1. Graylog `login-bruteforce` 이벤트 1건(`count()>8`) →
2. n8n(haedam-30)이 그 `src_ip`를 포털 112로 차단 + C 티켓 1건 →
3. 같은 IP의 새 요청 403 `IP_BLOCKED` (효과) →
4. **같은 계정의 다른 정상 출발지(`.12`·`.100~`)는 계속 로그인 200** (오차단 없음) →
5. 사람이 승인 후 해제 → 재접근 200, 티켓 restored → closed (원복).

## 3. 입력 (B)

- 도구: `python tools/s1_input_probe.py --run-id <id> --username <zz_…> --source <203.0.113.1x> --profile trigger`. 기본 계획 출력만, `--execute`는 Kali에서 출발지/32·경로·NTP·도구 해시 preflight 통과해야 실행.
- 한 출발지에서 같은 계정에 **401을 30분 창 안에 9~11회**, 약 100초 간격(한 번에 몰지 않음, 2분당 6회 미만). 403을 만나면 즉시 중단·재시도 없음.
- 회차마다 **계정·출발지·run_id·출력 파일을 분리**한다. 묶기 기준(username+src_ip)은 바꾸지 않는다.
- 정상 로그인은 다른 출발지(`.12`)에서 같은 계정으로 별도 수행.

## 4. 대조 (A, 포털 원본)

끝난 뒤 포털 VM에서 회차 구간을 뽑아 증적 폴더에 남긴다:

```bash
# 요약(사람 확인용)
ssh haedam@<포털 VM> "cd ~/haedam-portal-backend && .venv/bin/python - 'YYYY-MM-DD HH:MM:00' 'YYYY-MM-DD HH:MM:00' <공격 src_ip> <정상 src_ip>" < lab/s1s4/s1_check.py
# 원본 발췌(증적 JSONL)
ssh haedam@<포털 VM> "... --jsonl" < lab/s1s4/s1_check.py > portal-events.jsonl
# 지표 계산
python lab/s1s4/s1_metrics.py portal-events.jsonl --detected <D detected_at ISO, 차단 순서대로>
```

- `s1_check`는 username+src_ip로 묶어 30분 창 9건 초과의 **9번째 401**을 조건 충족으로 표시한다(= MTTD 시작점).
- `s1_metrics`는 조건 충족·MTTD·탐지→차단·탐지→403·해제→재접근 200을 회차별 표로 낸다.

## 5. 단계별 확인·판정 (어느 값이 어디서 나오나)

| 단계 | 어디서 | 기대 |
| --- | --- | --- |
| 조건 충족 | **포털 원본** 9번째 `auth.login_failed` (event_id) | MTTD 시작점. Graylog `condition_met_at`은 판정 창 끝이라 시작점으로 쓰지 않음 |
| 탐지 | D Graylog `detected_at` / 알림 | S1 이벤트 1건 |
| 자동 차단 | 포털 `web.ip_blocked`(호출자 `10.250.0.100`, target=공격 src_ip) · n8n 실행 · C 조치 줄 | 요청~응답 사이에 포털 차단 |
| 티켓 | C 저장소 | username+src_ip 키로 1건(새 티켓) |
| 효과 | 포털: 공격 src_ip 새 요청 **403**, 정상 src_ip·같은 계정 로그인 **200** | 오차단 0 |
| 원복 | 포털 `web.ip_unblocked` ↔ C released 시각·대상 일치 | 자동이 아니라 **수동 연결 해제**(D haedam-12 실제 해제 → C released). haedam-50은 실제 해제·C 기록 미지원 |
| 종료 | `blocked_ips` 0행, 티켓 closed, 계정 잠금 0 | 사전 상태로 복귀 |

- 지표(MTTD·탐지→차단)는 **파이프라인 지연**이지 사람 분석 시간이 아니다. Graylog 검색 주기(1분)를 함께 적어 시간 해상도를 밝힌다.
- 수집 불일치(포털 건수 ≠ Graylog 건수)가 있으면 숨기지 않고 종단 값(유실 포함)과 파이프라인 값을 병기한다.

## 6. 실측 2회 (이대로 재현되면 성공)

| 회차 | 날짜·환경 | 조건 충족 | MTTD | 탐지→차단 | 효과 | 원복 | 분류 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| S1-after-01 | 10/28 · `9507fce`·UDP | `.11`·`.13`·`.11` 재공격 3회 | 59.6·53.4·47.3초 | 1.0·0.57·0.55초 | 403·`.12` 200 | 수동 해제 3/3 | 통과 |
| S1-after-02 | 10/29 · `9507fce`·UDP | `.14` 14:46:39.430 | **99.1초(유실 포함)** / 4.2초(파이프라인) | 5.9초 | 403·같은 계정 `.12` 200 | 수동 연결 해제 | 통과(수집 불일치 1건) |

- S1-after-02의 99.1초는 9번째 신호가 **UDP에서 유실**돼 10번째 줄에서 발동한 것이다. TCP 전환 뒤 회차는 이 유실이 없어야 한다 → TCP 조건 재현으로 재확인.

## 8. 한계 (재현 결과 해석에 함께 적는다)

- 분산 출발지로 나눈 추측은 username+src_ip 묶기 밖(미탐, Q2).
- 같은 사무실 IP를 공유하는 정상 직원은 함께 막힌다(오탐 F4, Q5).
- 자동 해제 아님 — 사람 승인 후 수동 연결 해제. 자동 해제 완주는 미검증(haedam-50 `dry_run` 고정).
- 임계값(>8/30분)은 정상 기준선 측정 전 초안값. 정상 업무 30분 오탐은 측정 후.
