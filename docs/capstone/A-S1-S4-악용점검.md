# A · S1/S4 악용 점검 (대응 설계가 역이용되는가)

- 담당: whiteclover0542 (A) · 작성 2026-10-29 · 상태: 설계·소스 근거 분석. 랩 실측(공유 IP 동시 차단 등)은 오후 시험에서 대조.
- 근거: [공격 시나리오](A-S1-S4-공격시나리오.md), [정상 패턴 정의서](A-S1-S4-정상패턴.md), [포털 API](../haedam/PORTAL-API.md), backend `admin/__init__.py`(unlock/reset), A순서 178.
- 핵심 질문(A순서 178): ① S1을 계정 잠금이 아닌 출발지 차단으로 둔 이유가 실제로 해소되는가 ② 같은 출발지를 공유하는 정상 사용자가 함께 막히는가 ③ S4 잠금이 같은 악용 문제를 만드는가 ④ 오탐 해제 비용.

## 1. S1 — 출발지 차단이 "계정을 일부러 잠그는 악용"을 막는가

| 악용 시도 | 결과 | 근거 |
|---|---|---|
| 공격자가 남의 공무원 계정에 실패를 퍼부어 **계정을 잠그려 함** | **불가.** S1 대응은 계정 잠금(111)이 아니라 **출발지 차단(112)**. 실패를 아무리 보내도 잠기는 건 공격자 출발지, 피해 계정은 유지 | S1 대응=112, 잠금은 S4에만(기획서·A순서) |
| 피해 계정 소유자의 정상 로그인 | **유지.** 차단은 src_ip 단위라 같은 계정의 **다른 정상 출발지(.100~)는 계속 로그인** | S1 효과 정의, 오후 R1에서 `.12` 200 확인 예정 |

→ ① 해소됨. S1을 잠금으로 뒀다면 공격자가 정상 계정을 잠그는 길이 열리므로, 출발지 차단 선택이 이 악용을 막는다.

## 2. 공유 출발지 collateral (② — 남는 위험)

- S1 집계 키는 username+src_ip이나 **차단 단위는 src_ip**다. 같은 공인 IP(NAT 뒤 사무실)를 **정상 사용자가 공유**하면, 그 IP가 차단될 때 함께 403.
- 완화:
  - 차단은 출발지 단위라 **계정 자체는 유지** → 공유 IP가 막혀도 피해자는 다른 정상 출발지로 로그인 가능.
  - 임계 초과(30분 8회 초과) + 정상 패턴 상한(오타 ≤4, 30분 실패 ≤8, [정상패턴 F1~F4](A-S1-S4-정상패턴.md))으로 정상 공유 사용자가 임계에 닿을 확률을 낮춤.
  - 관리망·대응 호출자(허용 CIDR)는 block 자체를 403으로 거부(자기 차단 방지, `RESPONSE_ALLOWED_CIDRS`).
  - 전제: 실제 공격 출발지는 외부(203.0.113.x), 정상 공무원은 내부망/다른 출발지. 단일 NAT 공유가 크면 위험이 커지므로 **환경 전제를 결과표에 명시**.
- 랩 대조(오후): 같은 출발지를 공유하는 정상 요청이 차단에 함께 걸리는지 1건 확인(없으면 "환경상 공유 IP 미사용"으로 표기).

## 3. S4 — 잠금이 같은 악용을 만드는가 (③)

| 악용 시도 | 결과 | 근거 |
|---|---|---|
| 공격자가 **실패만** 퍼부어 남 계정을 S4로 잠그려 함 | **불가.** S4는 `login-bruteforce` + `login-success` **두 rule(card(rule)>1)** 이 같은 username+src_ip에 모여야 발동. 성공은 비번을 알아야 하므로 실패만으론 미발동 | S4 조건(A순서·정상패턴 §1) |
| 공격자가 피해자 비번을 **모른 채** 잠그기 | **불가.** 성공 신호를 못 만듦 | 위와 동일 |

→ S4 잠금은 "실패 뒤 성공(실제 탈취 정황)"에만 걸리므로, 실패만으로 정상 계정을 잠그는 악용은 안 생긴다. 단 **묶기 키가 username+src_ip**라, 공격자가 여러 출발지로 나눠 추측하면 S1·S4 모두 **범위 밖**(알려진 한계, 결과표에 명시).

## 4. S4 오탐 비용과 해제 경로 (④ — 소스 확인으로 해소)

- S4 오탐 1건 = 정상 공무원 계정 잠김 + 기존 세션 회수. 영향: 재로그인 필요.
- **비번 유지 해제 경로 존재 확인**: `POST /admin/users/{id}/unlock`(reason_code=false_positive)는 **비밀번호를 유지**한 채 잠금만 해제한다(`admin/__init__.py:104-123`, 주석 "S4 오탐 확인 시 비밀번호를 유지한 채 잠금만 푼다, B 정책 10/22"). 탈취 의심일 때만 `reset-password`로 비번 재설정.
  - → A순서 178의 "비번 유지 unlock 경로를 둘지 B 확인" **해소**: 이미 있음. 오탐이면 공무원이 **비번을 바꿀 필요 없이** 관리자 해제로 복귀.
- 잔여 비용: unlock·reset 모두 **회수된 세션은 복원하지 않음** → 정상 공무원도 **재로그인 1회** 필요. 이게 오탐의 실제 사용자 영향이며 해제 시간·절차와 함께 결과표에 기록.
