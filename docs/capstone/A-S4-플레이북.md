## 4. 해제 (사람이 판단)

| 판단 | 경로 | 비밀번호 | 세션 | 화면 |
| --- | --- | --- | --- | --- |
| 오탐 | 관리자 세션 `POST /api/v1/admin/users/{id}/unlock` `{"reason_code": "false_positive"}` | 유지 | 회수된 세션 복원 안 함, 새 로그인 | 있음 — "오탐 해제(비밀번호 유지)", **잠긴 계정에만 표시**(frontend #3 `2836a42`, 10/28 17:00 수동 잠금으로 확인: `reason_code: false_positive`, 기존 비밀번호 로그인 200) |
| 탈취 의심·확인 | 관리자 화면 "비밀번호 재설정 · 잠금 해제" 또는 `POST /response/accounts/{id}/reset` | 새 임시 비밀번호 | 회수, 새 로그인 | 있음 |

1. 해제 전: 같은 계정의 열린 티켓·진행 중 작업을 C·D와 대조한다.
2. 확인: `auth.password_reset`(재설정) 또는 `auth.account_unlocked`(unlock), `locked=0`, **로그인 없이 새로고침해도 비로그인**(이전 세션 복원 안 됨), 새 로그인 성공. 10/28 실제(S4-before-03): 재설정 10:55:32.422 → 새로고침 비로그인 → 새 로그인 10:55:51.594, DB 세션 1개.
3. C가 티켓 released → 사람이 close.

## 5. 사람이 판단할 경계

- **오탐 비용:** 10/28 잠금 → 재설정 1분 43초. 화면에 unlock 버튼이 없으면 오탐이어도 정상 사용자가 비밀번호를 바꿔야 한다. → 10/28 17:00부터 오탐 해제 버튼으로 비밀번호를 유지한 채 해제할 수 있다(잠금 16:59:02 → 해제 16:59:27, 25초).
- **해제 뒤 2차 오탐:** 재설정 직후 사용자가 새 비밀번호를 9번 잘못 입력해 같은 계정·출발지 401 10건(30분 안) → 성공. S1·S4 조건을 모두 채웠다(10/28, 정의 미반입이라 조치 없음). 재설정 비밀번호는 사용자에게 정확히 전달하고, 첫 로그인은 관리자가 지켜본다(완화책 D·B와 미정).
- **수집 유실:** 같은 시험에서 포털 401 10건 중 Graylog 9건(UDP GELF, 10:20:06 1건 유실). 경계 근처 입력은 판정이 1건 차이로 바뀔 수 있다.
- **공격자가 일부러 잠그기:** S4는 성공이 있어야 발동하므로 비밀번호를 모르는 공격자는 S4로 남의 계정을 잠글 수 없다. 반복 실패만으로는 S1(출발지 차단)이 걸린다.
- **기록:** 비밀번호·`X-Response-Key`·세션 값은 일지·증적·캡처에 남기지 않는다. 증적은 `docs/capstone/evidence/S04/{before,after}/<run_id>/`.
