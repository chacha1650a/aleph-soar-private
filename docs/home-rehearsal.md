# 집 리허설과 학원 인수 안내 · 2026-10-24

**집에서는 모의 IP 차단/해제의 조회·판단·예약·반영·효과 확인·티켓 기록·실패 복구까지 구현/검증했다.** 실제 포털/pfSense/Wazuh 호출 어댑터, n8n 배포·전체 호출자의 조율 참여, 학원 연결/실측은 완료하지 않았다. 아래 합성 결과는 S12나 다른 케이스의 실제 성능/성공 횟수로 계산하지 않는다. 최신 팀 현황은 [PROGRESS](PROGRESS.md)다.

## 한 명령으로 재현

프로젝트 .venv의 Python과 Node.js가 필요하다. 이 PC는 Python3.12·Node24.15.0을 사용했다. .venv가 없으면 `python tools/bootstrap.py`, 이후 Windows에서는 `.venv/Scripts/python.exe`로 실행한다. 먼저 [C PR55 고정 패치의 새 검증 체크아웃](../patches/ticket-store-pr55/README.md#다른-pc에서-같은-패치-검증)을 준비한다. 이름이 다르면 아래 경로를 바꾼다.

```powershell
python tools/rehearse_integration.py --ticket-source .local/ticket-pr55-final-20261024 --output .local/home-rehearsal-new
```

이미 있는 output 폴더는 덮어쓰지 않는다. C head와 diff가 배포한 고정 패치에 정확히 일치하는지 확인하고, 임시 gate/모의 대상/C 저장소 DB와 합성 키를 사용한다. **모의 대상은 SQLite 상태이며 실제 HTTP 차단/해제 API가 아니다. C 기록은 로컬 Flask test client로만 수행한다.** 네트워크 POST·실제 키·학원 DB·n8n 기동·설정 적용은 없다. 끝나면 시험 DB를 정리한다.

출력은 `report.json`(synthetic_only·범위·C 기준 커밋/패치·실행 코드 해시·6종 결과·남은 일), `report.md`(요약), `manifest.json`(보고서 해시·complete)이다. 모든 검증을 통과한 뒤 보고서를 쓰며, 중단/부분 쓰기의 폴더는 complete manifest가 없으므로 성공 보고서가 아니다. `actual_device_calls:0`, `live_n8n_verified:false`를 유지한다. 실제 조회/대상 효과/학원 완료 증적으로 바꾸지 않는다.

이번 직접 실행 결과를 비밀값 없는 합성 증적으로 보존했다: [요약](capstone/evidence/home-rehearsal-20261024/report.md), [JSON·실행 코드 해시](capstone/evidence/home-rehearsal-20261024/report.json), [manifest](capstone/evidence/home-rehearsal-20261024/manifest.json). 원본 로컬 결과와 바이트가 같다. 이 보고서는 위 모의 흐름의 검증이며 전체 pytest 건수는 개인 일지에 별도로 기록한다.

| 집 리허설 | 실제 확인한 것 |
| --- | --- |
| normal | 모의 적용→효과 확인→기록→해제, 같은 요청 replay, restored에서 새 주기 보류→기존 티켓 명시적 닫기→새 티켓 생성/모의 해제 |
| overlap | 기본 리허설은 A username·D IP 묶음이 겹치면 해제 보류. 후속 [소유권 반납 정책 후보](shared-release-candidate.md)는 별도 모의 구현/검증이며 운영 미채택 |
| after_target | 모의 대상 반영 뒤 응답 불명: gate pending, 후속 해제 busy |
| after_record | 기록 반영 직후 중단: pending 유지, 같은 키/본문의 기록 재조회/재전송으로 복구 |
| record_unavailable | 대상 반영 후 C 기록 실패: 재기동 후 대상 영수증/현재 상태 대조→기록만 복구 |
| ack_loss | C에 반영됐지만 ACK 유실: 같은 기록 키/본문 replay, 모의 대상 재호출 없음 |

모의 대상의 상태와 요청 영수증은 한 SQLite 트랜잭션으로 저장한다. 같은 논리 요청ID/다른 자원·동작은 충돌이며, 원래 영수증의 완료 시각으로 기록 본문을 재생성해 복구 때 본문이 달라지는 409를 피한다. 복구는 이전 실행 종료 확인이 필요하고, 현재 모의 상태가 원래 영수증과 다르면 보류한다. 대상 ledger가 없으면 새 빈 DB로 대체하지 않는다. **실제 제품이 같은 원자성/영수증 조회를 제공한다는 뜻은 아니다.**

구현은 [simulated_execution.py](../tools/simulated_execution.py), [리허설 CLI](../tools/rehearse_integration.py), [회귀](../tests/test_simulated_execution.py)다. 실제 대상 객체를 끼우는 플러그인/허용 스위치는 없다. 기존 guard의 allow_target_call=false를 무시해 운영 호출을 켜지 않는다. 합성 모드만 별도의 SQLite 모의 대상을 호출한다.

## 학원에서 처음 할 일

먼저 **기존 B/D S10 준비 표본**을 대조한다. ICMP ID25265/seq164의 원문 수신·정규화 대기가 남아 있으므로 새 본 입력/재송신부터 시작하지 않는다. C/D 티켓 연결 준비와 A 포털 상태 확인은 측정/파일 소유가 겹치지 않는 범위에서 병렬로 할 수 있다.

| 사람 | 준비 회신1회에 포함할 것 | 실행 뒤 최종 회신1회 |
| --- | --- | --- |
| A | 실제 포털 배포 버전·health·DB·잠금/해제/차단 경로와 현재 상태 | 원본 ID·앱/DB 결과·정상 접근/원복 근거 |
| B | 기존 VPN/반환 경로·리스너/허용 이력·기존 입력 ID/관측창 | 입력/전송/원본 수·C/D 조회와 맞는 ID/시간 범위 |
| C | 채택 티켓 head/패치·별도 시험 DB·키 주입·기동 상태·읽기/기록 공개 범위 | 저장 재조회/재시작 보존·조치별 효과/원복·샘플/실제 구분 |
| D | 실제 채택 워크플로/파서·HTTP status/body/query·dry_run/실제 호출 분리·실행 조율 위치 | 원문 수신/정규화/정의·n8n 실행ID/실제 HTTP·티켓/효과/원복 근거 |

좁은 B/D 정규화 대조에 A/C의 완료를 선행 조건으로 추가하지 않는다. 모두 같은 시험ID·버전·시간창·공통 보고서를 읽고 변경/오류 때만 관련 준비를 재확인한다. 다른 LLM 답변을 반복 중계하는 대신 [status --seat](lab-check-team-run.md) 결과를 같은 실행 묶음으로 공유한다. 실제 발송은 사용자/팀이 수행하며 이번 작업에서 팀 메시지를 보내지 않았다.

그다음 C/D가 정책을 확정하고 별도 시험 DB로 연결한다. 키 없음/틀림, 정상 조회/기록, 같은 키 재전송·다른 본문409, 재시작 보존, 다른 자원의 분리와 공유 소유권 보류를 확인한다. C 제안의8088/8089·VPN 주소가 현재 실행 환경과 맞는지는 현장에서 확인한다. 기존 경로/최소 허용을 먼저 대조하며 여기서 NAT/방화벽 적용 명령을 만들거나 실행하지 않는다.

## 여전히 확정·구현이 필요한 것

1. **C/D의 자원 식별/소유권 반납 정책.** 논리 반납/유지 재요청/마지막 물리 해제의 [후속 정책 후보](shared-release-candidate.md)를 집에서 모의 구현했다. C/D 채택과 인증된 운영 API/취소·재개·소비자 연결은 미완료다. 현 C/D 계약은 여전히 보수적 보류이며 자동 교체하지 않는다. 티켓 단위 asset_id와 다중 집행 자산, 실제 해제 동작 짝도 확인 필요다.
2. **운영 실행 위치.** D n8n과 Python/SQLite 조율을 어느 호스트/서비스에서 연결할지 미정이다. 모든 적용/해제 호출자의 같은 조율 참여·운영 DB 식별/복원·우회 수동 실행 제어를 확보해야 한다. 여러 PC의 DB 복사나 개별 임시 DB로 대체할 수 없다. 전역 권한을 변경해 노드를 켜지 않았다.
3. **실대상 계약과 복구.** 대상별 안정된 요청 키·멱등성·상태/영수증 조회·인증/허용 대상·전체 마감/재시도 정책을 확정하고 실제 어댑터를 구현한다. 모의 receipt를 실제 포털/pfSense/Wazuh의 증거로 사용하지 않는다. 실대상 호출/반영이 불명확하면 pending을 유지하며 무조건 재호출하거나 finally로 잠금을 풀지 않는다.
4. **현장 인수.** 위 연결 후 승인된 별도 구간에서 실제 효과·독립 정상 접근·원복·로그/티켓 ID·시각·재시작/장애를 대조한다. 합성6종 결과를 실측 반복 횟수에 포함하지 않는다. 실제 성능/팀 메시지 감소/통합 속도는 아직 측정하지 않았다.

집에서 만든 코드를 적용 가능한 운영 시스템 전체로 완료 처리하지 않는다. 실제 어댑터/n8n 배포와 현장 시험은 남아 있으며, 이 문서는 필요한 결정과 첫 실행 순서를 한 번에 인계하는 자료다.
