# 해담시청 작업 순서와 인수 조건

10/19 집 세션에서 사용자가 프론트·백 구현을 맡고 React + Flask를 선택했다. H00~H03의 로컬 개발 환경·포털 구현과 검증을 진행한다([brief](MVP-TASK-BRIEF.md), [계약](PORTAL-API.md)). H04는 이벤트·계정 대응 API의 로컬 경계만 구현하며 외부 관제·pfSense·FIM은 미연동, H05의 두 PC 통합·독립 재현은 미완료다. 기존 `orchestration/workplan.json`의 P01/B01/U01은 과거 capstone 스켈레톤 작업이며, 새 포털의 코드 수정 경계는 이 카드와 brief에 적힌 별도 두 저장소다. 도구의 ready 출력은 팀 합의·공유 완료 증거가 아니다.

## H00 — 저장소·개발 기준 정리

- 담당: 포털 구현 김명준 + Codex. 기존 A 공통 기반 책임 유지, 독립 리뷰어 별도 배정.
- 범위: 두 비공개 저장소 생성·스켈레톤 초기화, README·의존성·개발 환경 설정. 저장소 생성 이후에도 앱 실행 환경은 별도로 구성한다.
- 결정할 것: 프론트 기술, Python 버전, 인증·세션·CSRF, DB 연결·마이그레이션, 개발 주소, 배포 경로와 프록시.
- 완료 조건: 다른 팀원이 각 README만으로 개발 환경을 준비하고 실제 실행·검증 명령을 재현한다. 사용한 공통 규칙 커밋과 미연결 도구를 기록한다.

## H01 — 최초 화면·API 계약

- 선행: H00, 기존 P01의 관련 계약 합의.
- 범위: capstone `docs/API-CONTRACT.md`·`contracts/`와 양쪽 저장소의 계약 복사본·소비자. 원본 파일은 조율한 한 담당자가 수정한다.
- 합의: 로그인·로그아웃·현재 사용자, 민원 작성·본인 목록·상세·처리 상태, 관리자 작업의 권한표, 요청·응답·오류·CSRF·페이지 처리. 경로는 계약 작성 시 정한다.
- 완료 조건: 정상·실패·타인 민원 접근 거부 예시를 양쪽에서 같은 의미로 해석하고, 합성 예시와 실제 API를 구분한다.

## H02 — 백엔드 정상 업무

- 선행: H01. 작업자 김명준 + Codex, 독립 리뷰어 별도 배정. 기존 A 공통 기반 책임 유지.
- 범위: backend `src/haedam_portal/{auth,petitions,admin}/`, `tests/`, DB·마이그레이션과 실행 설정.
- 연결: 프론트 API 소비자, 이벤트 담당 D, 망 담당 B. 비밀값은 전달하지 않는다.
- 완료 조건: 실제 로그인·세션 종료·민원 저장·역할/소유권 검사·상태 전이·재시작 후 재조회 검증. 무권한·잘못된 입력·타인 조회가 거부된다. 이벤트에는 민감 데이터가 없다.

## H03 — 프론트 정상 업무

- 선행: H01. H02 구현 중 계약의 합성 예시로 화면 개발 가능. 실제 구현은 Flask API에 연결했다.
- 범위: frontend `src/{pages,components,api,styles}/`, `tests/`. 프론트 기술 확정 후 파일과 도구를 추가한다.
- 연결: H02의 실제 API, C가 제공하는 관제 대시보드 링크. 화면은 계정 권한과 API 응답을 반영한다.
- 완료 조건: 로그인 → 민원 작성 → 새로고침 후 목록·상세 조회 → 담당자 처리 → 시민 상태 확인을 실제 백엔드로 재현한다. 빈 목록·401/403 등 계약 오류·연결 실패·좁은 화면을 확인한다. API 연결 전에는 화면 개발 완료와 실제 통합 완료를 구분한다.

## H04 — 로그·대응·원복 연결

- 선행: H02·H03 정상 업무 통합. 계약 변경은 별도 합의.
- 범위: backend `integration/`와 이벤트·대응 API, frontend 관리자 링크·상태 안내, capstone의 대응 워크플로·탐지·계약·통합 증적.
- 연결: A 포털·대응 API, B pfSense·VPN·Suricata, C Wazuh·대시보드, D Graylog·n8n. 실측 담당은 기존 자리 담당을 따른다.
- 완료 조건: 합의한 케이스별 탐지 → 실제 대상 상태 변화 → 티켓 → 효과 확인 → 원복 증거를 남긴다. 반복 호출·실패·자기 차단 방지·S4 세션 회수를 검증한다. S7은 실제 배포 파일 경로·해시, S12는 민원 API 지연·회복을 확인한다.

## H05 — 두 저장소 통합 재현

- 선행: H04. 독립 재현자는 구현자 외 팀원 중 배정.
- 범위: 각 저장소 README·테스트, capstone의 망 허용표·실측표·시연·원복 절차.
- 완료 조건: 프론트 커밋 + 백엔드 커밋 + 계약 커밋 + 배포 설정 버전을 함께 기록한다. 지정 PC 두 대에서 정상 대조·보강 전후·반복 측정·실패·복구를 재현하고 미확인 항목을 남긴다.
- 2026-10-20 보강: [관제 가용성 검증 계획](MONITORING-CAPACITY-PLAN.md)에 따라 RPS/EPS, 검색 가능 지연·누락, 적체·자원, 정상 시민 영향, 서비스/관제 복구 시간을 별도로 기록한다. 실제 관제 시험은 미실행이며, Kafka 도입 판단은 측정 후 진행한다.
