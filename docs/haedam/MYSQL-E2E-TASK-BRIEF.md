# MySQL 브라우저 통합 검증

- 작업: H02/H03의 MySQL 정상 업무·재시작 검증. 사용자 지시 `1번 진행하자`, 담당 김명준 + Codex. 기존 `codex/haedam-portal-mvp`의 검증 범위를 확장한다.
- 수정 범위: backend `tools/e2e_server.py`와 새 MySQL 브라우저 실행 도구, frontend Playwright 설정·추가 영속성 테스트, 양쪽 README/VERIFICATION, capstone 결과 핸드오프. 업무 API·DB 스키마·기존 보안 케이스 계약은 변경하지 않는다.
- 환경: 고유 이름·생성 비밀번호·루프백 임의 DB 포트·자원 제한을 둔 일회용 MySQL 8.4. 기존 5000 서버와 SQLite/다른 컨테이너를 보존한다. 합성 데이터만 사용한다.
- 인수: 실제 MySQL dialect/version과 마이그레이션을 확인하고 기존 브라우저 11건을 실행한다. 추가로 시민 신청→서버 프로세스 교체→같은 시민 세션의 재조회→담당자 배정/답변→서버 프로세스 교체→시민·담당자 재조회, 상태/답변/이력/한글·4바이트 문자/타인 접근 거절을 검증한다.
- 증거: UI·API 결과와 MySQL 직접 감사 결과를 구분한다. 실제 프로세스 교체와 DB 데이터를 관찰하고 비밀번호·DB URL·쿠키·토큰을 결과 파일/콘솔에 남기지 않는다. 관리용 재시작 HTTP API는 추가하지 않는다.
- 정리: 성공·실패 모두 이 실행이 만든 서버·컨테이너만 종료한다. 재현 명령·정확한 버전·결과·미검증 범위를 핸드오프와 기존 Draft PR에 기록한다. 팀 서비스 VM 배포·백업 복원·MySQL 서버 재시작·외부 관제/두 PC 시험은 이번 인수에 포함하지 않는다.
