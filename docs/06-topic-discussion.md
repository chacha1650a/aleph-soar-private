# Claude와 주제 논의 시작하기

준비일: 2026-10-15 (KST) · 상태: 조건 확인·주제 논의 중

## 이번 대화의 목적

팀이 끝까지 구현하고 시연할 수 있는 프로젝트 주제와 MVP를 고릅니다. 이 저장소의 SOAR 기획은 출발점이며, 강의 예시를 팀의 최종 주제로 확정한 상태는 아닙니다.

## 확인된 배경

- NoBugs-Aleph 조직의 팀 프로젝트 준비용 저장소입니다.
- 사용자 제공 자료 167·168은 스마트팩토리–본사 환경의 4계층 방어, 로그 상관, 자동 대응, 티켓, 원복을 다룹니다.
- 참고 기술은 Cloudflare, pfSense, Flask, Wazuh, MySQL, Graylog, n8n이며 버전과 도입 여부는 미정입니다.
- 기존 `flask-board-team` 실습 저장소가 있습니다. 재사용 가능성은 검토 전입니다.
- 현재 저장소에는 기획 문서와 공통 작업공간 스켈레톤이 있습니다. 앱 시작 화면·상태 API만 실행 가능하며 인증·탐지·대응은 미구현입니다.
- 사용자가 확인한 기간은 2주, 참여 인원은 4명입니다. 전원이 Claude를 사용하고, 사용자와 팀원 1명은 Codex도 사용합니다.
- 사용자가 선택한 중점 방향은 계정 이상 탐지·자동 대응, 침해 흐름 관제, 권한·데이터 접근 추적입니다.
- 현재는 팀원이 후보 중에서 주제를 고르는 단계입니다. 앞서 세 방향을 묶은 [통합 주제·MVP 제안](07-topic-decision.md)은 참고안이며 채택된 주제는 아직 없습니다.

## 남은 확인 질문

1. 정확한 제출일·필수 제출물·평가 기준은 무엇이며, SOAR나 4계층 구성이 필수인가요?
2. 팀원 4명의 자신 있는 분야와 실제 투입 가능 시간은 어느 정도인가요?
3. 사용할 수 있는 PC·VM·서버·예산은 어느 정도인가요?

이미 확인된 4인·2주·관심 방향은 다시 질문하지 않습니다. 미확인 조건은 가정으로 표시하며 AI 도구 보유만으로 숙련도나 작업 시간을 추정하지 않습니다.

## 비교할 출발 후보

팀원에게 제시할 최신 선택 자료는 [후보 8개와 투표 양식](10-topic-candidates.md)입니다. 아래 4개는 제공 자료에서 파생한 초기 토론 소재이며 우선순위·채택 추천이나 구현 가능성 검증 결과가 아닙니다.

| 후보 | 문제와 사용자 가설 | MVP에서 보여줄 장면 | 범위를 정할 질문 |
| --- | --- | --- | --- |
| A. 스마트팩토리 4계층 통합 관제 | 공장·본사 관제 담당자가 흩어진 사건을 연결하기 어려움 | 여러 계층의 샘플 신호를 한 사건과 티켓으로 연결 | 4계층을 모두 실제 장비로 구현해야 하나? |
| B. 계정 이상 징후 대응 | 사내 서비스 관리자가 계정 이상을 늦게 발견함 | 인증 이벤트 탐지 → 테스트 계정 잠금 → 해제 확인 | 일반 로그인 알림과 구별되는 핵심 기능은 무엇인가? |
| C. 권한·데이터 접근 추적 | 관리자가 권한 변화와 민감 조회의 관계를 파악하기 어려움 | 앱 권한 이벤트와 DB 접근 로그를 근거로 사건 설명 | 감사 로그 수집과 정상 접근 구분이 가능한가? |
| D. 대응·원복 이력 관리 | 운영자가 자동 대응 이유와 복원 상태를 확인하기 어려움 | 사건 근거 → 대응 선택 → 테스트 상태 변화 → 원복 이력 | 기존 티켓 도구와 구별되는 사용자 흐름은 무엇인가? |

후보별로 필수 기능 3개 이내, 제외 범위, 3분 시연 흐름, 첫 검증 과제를 함께 적습니다. 실제 장비 연동과 샘플 기반 시연을 명확히 구분합니다.

## 비교 기준

| 기준 | 확인할 내용 |
| --- | --- |
| 문제의 구체성 | 누가 언제 겪는 문제이며 해결 전후가 명확한가? |
| 과제 적합성 | 확인된 평가 기준과 필수 요건에 맞는가? |
| 완주 가능성 | 팀 역량·시간·장비로 핵심 경로를 구현할 수 있는가? |
| 시연·검증 | 짧은 시연과 정상·오탐·원복 결과로 효과를 보여줄 수 있는가? |
| 차별성 | 참고 예제와 비교해 팀이 직접 설계한 가치가 있는가? |
| 분업 가능성 | 담당별 산출물과 연결 지점이 명확한가? |

평가는 근거를 함께 씁니다. 정보가 없으면 ‘확인 필요’로 두며 임의의 점수 합계로 결론을 확정하지 않습니다.

## 이번 논의에서 얻을 결과

- 후보 3~5개 비교표와 잠정 우선 후보 1개
- 우선 후보의 한 문장 문제 정의와 핵심 사용자
- MVP 기능, 제외 범위, 3분 시연 흐름
- 남은 불확실성과 이를 확인할 첫 과제
- 확정 사항과 미정 사항을 구분한 결정 기록

결과 기록은 [주제 결정 기록](07-topic-decision.md)을 사용합니다. 일정은 실제 제출일이 확인된 뒤 잡습니다.

## 시작 방법

프로젝트 폴더의 PowerShell에서 실행합니다.

```powershell
.\Start-ClaudeDiscussion.ps1
```

스크립트는 Claude Code를 계획 모드로 열고 [시작 프롬프트](../prompts/claude-topic-discussion.md)를 읽어 진행하도록 요청합니다. 실행 정책 때문에 막히면 README의 대체 명령을 사용합니다. 모델은 사용자 기본 설정을 사용합니다. 첫 실행에서 로그인이나 폴더 신뢰 확인 화면이 나오면 사용자 계정으로 진행합니다.

Claude 웹·앱에서 대화할 경우에는 시작 프롬프트와 이 문서, 필요한 기획 문서를 함께 제공하세요. 해당 환경이 로컬 파일에 접근할 수 있다고 가정하지 않습니다.
