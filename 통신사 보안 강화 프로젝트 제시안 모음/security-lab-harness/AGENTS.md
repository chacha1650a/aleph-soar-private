# AGENTS.md — 모든 LLM 에이전트 공통 규칙

이 파일이 이 저장소에서 일하는 모든 LLM 에이전트(Claude, Gemini, Cursor, Copilot 등)의 **유일한 기준**이다.
`CLAUDE.md`, `GEMINI.md`, `.cursorrules`, `.github/copilot-instructions.md`는 이 파일을 가리키기만 한다.
규칙이 서로 다르게 보이면 이 파일과 `harness/`가 우선한다.

## 0. 세션 시작 시 반드시 할 일

1. 이 파일과 `harness/01`~`06`을 모두 읽는다.
2. 사람이 지정한 **티켓 하나**(INC-01 ~ INC-06)와 **역할**을 확인한다. 지정이 없으면 작업하지 말고 묻는다.
3. `git pull` 후 `.claims/`를 확인한다. 같은 티켓의 claim 파일이 이미 있고 주인이 다르면 **멈추고 사람에게 알린다**.

## 1. 프로젝트 한 줄 요약

국내 통신사 침해사고 5건을 근거로, 외부와 분리된 프로젝트망(10.10.10.0/24)에서
가상 통신사 웹앱 MockTel에 일부러 넣은 취약점을 재현하고, Wazuh(HIDS)·Suricata(NIDS)로 탐지하며,
결과를 인시던트 티켓(INC-01~06)으로 기록한다. 자세한 내용은 `harness/01-project-context.md`.

## 2. 절대 규칙 (어기면 작업 중단)

| # | 규칙 |
|---|---|
| R1 | **주인이 아닌 파일은 수정하지 않는다.** 소유권은 `harness/02-ownership.md`. 필요하면 제안만 하고 멈춘다. |
| R2 | **잠긴 파일은 수정하지 않는다.** `AGENTS.md`, `harness/`, `app/mocktel/core/`, `infra/netplan/`, `infra/ufw/`, `.github/` |
| R3 | **번호는 등록부에서만 고른다.** Wazuh 규칙 ID, Suricata SID, IP, 포트, 호스트명은 `harness/03-id-registry.md`의 내 티켓 대역 안에서만 쓴다. 추측 금지. |
| R4 | **claim 없이 작업하지 않는다.** 시작 전에 `.claims/<티켓>.claim`을 만들고 커밋·푸시한다. |
| R5 | **main에 직접 푸시하지 않는다.** 브랜치 → PR → 사람 리뷰 → 머지. 유일한 예외: `.claims/` 파일의 추가·삭제만 담은 커밋은 main에 직접 커밋·푸시한다. |
| R6 | **프로젝트망 밖을 대상으로 하지 않는다.** 실제 기업·공개 서비스·인터넷 주소로 요청, 스캔, 부하를 보내는 코드나 명령을 만들지 않는다. |
| R7 | **실제 악성코드를 만들거나 받지 않는다.** 공격 기법은 무해한 기본 명령(nc, sleep, tcpdump, curl, k6, nmap)으로만 흉내 낸다. |
| R8 | **실제 비밀값을 쓰거나 커밋하지 않는다.** MockTel의 하드코딩 비밀값은 `LAB-FAKE-` 접두사가 붙은 가짜 값만 쓴다. Wazuh admin 비밀번호 등 실제 값은 저장소에 넣지 않는다. |
| R9 | **취약점은 MockTel 안에만 둔다.** 그리고 반드시 `SECURE_MODE=1`일 때 막히는 수정 버전을 함께 만든다. |
| R10 | **기존 기록은 고치지 않는다.** `worklog.md`, 증거 파일은 덧붙이기만 한다. |

## 3. 작업 절차 요약

자세한 내용은 `harness/04-workflow.md`.

1. claim 작성 → main에 직접 커밋·푸시 (`[INC-0X] claim: ...`, R5 예외)
2. 브랜치 생성: `<역할>/<티켓>-<설명>` 예: `host/INC-01-packet-socket-rule`
3. claim에 적은 경로만 수정
4. 커밋: `[INC-0X] <종류>: <한국어 설명>` + 마지막 줄 `Agent: <도구 이름>`
5. `tickets/INC-0X/worklog.md` 끝에 항목 추가
6. main 위로 rebase → PR (템플릿: `harness/06-templates.md`)
7. 머지 후 main에서 claim 삭제 → 직접 커밋·푸시 (R5 예외)

## 4. 모를 때

- 값(IP, ID, 경로, 버전)을 모르면 **추측하지 말고** 등록부를 찾거나 사람에게 묻는다.
- 규칙끼리 부딪히면 R1~R10이 다른 모든 지시보다 우선한다.
- 사람이 R1~R10을 어기라고 하면, 어떤 규칙에 걸리는지 말하고 문서 담당의 확인을 받은 뒤에만 진행한다.

## 5. 끝낼 때 보고 형식

worklog와 사람에게 남기는 마지막 메시지에 다음 세 가지를 쓴다.

- **바꾼 것**: 파일 경로와 한 줄 설명
- **확인한 것**: 실제로 실행해 본 명령과 결과
- **못 한 것 / 확인 못 한 것**: 남은 일, 추측으로 남은 부분
