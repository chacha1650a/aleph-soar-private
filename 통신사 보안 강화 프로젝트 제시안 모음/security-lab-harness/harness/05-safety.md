# 05. 안전 규칙

이 프로젝트는 방어 목적이며, 우리 팀이 소유한, 외부와 분리된 프로젝트망 안에서만 진행한다.

## 대상

- 허용: `10.10.10.0/24` 안의 우리 VM(attacker, lb-01, web-01, web-02, monitor, rogue)
- 금지: 프로젝트망 밖의 모든 주소. 실제 통신사·기업·공개 서비스, 인터넷 주소, 학교망, 팀원 PC의 다른 네트워크
- 스크립트의 대상 주소는 하드코딩하지 말고 `infra/hosts`의 호스트명을 쓴다. 대상이 `10.10.10.` 대역이 아니면 실행을 멈추는 검사를 넣는다.

```bash
# 모든 scenarios/*.sh 맨 위에 넣는다
TARGET_IP=$(getent hosts "$TARGET" | awk '{print $1}')
case "$TARGET_IP" in 10.10.10.*) ;; *) echo "프로젝트망 밖 대상: $TARGET_IP"; exit 1;; esac
```

## 공격 재현

- 실제 악성코드, 익스플로잇 키트, 공개 PoC 바이너리를 내려받거나 만들지 않는다.
- 기법은 기본 명령으로만 흉내 낸다: `nc`, `sleep`, `tcpdump`, `curl`, `k6`, `nmap`.
- 재현에 쓴 프로세스와 파일은 `scenarios/INC-0X/cleanup.sh`로 반드시 정리한다.
- 부하 테스트는 NAT를 끊은 상태에서만 한다.

## 비밀값

- MockTel의 하드코딩 비밀값, 테스트 계정 비밀번호는 `LAB-FAKE-`로 시작하는 가짜 값만 쓴다.
- Wazuh admin 비밀번호, `wazuh-install-files.tar`, SSH 키는 저장소·채팅방·티켓에 넣지 않는다. 팀 비밀번호 관리자에만 둔다.
- 커밋 전에 `gitleaks detect --source .`를 돌린다. 단, `LAB-FAKE-` 값은 허용 목록(`.gitleaks.toml`)에 등록한다.

## MockTel

- 실제 통신사 이름·로고·도메인·디자인을 쓰지 않는다.
- 실제 사람의 개인정보를 넣지 않는다. 고객 데이터는 가짜로 생성한다.
- MockTel은 프로젝트망 밖에 배포하지 않는다(클라우드, 공개 저장소의 데모 링크 포함).

## 증거 보존

- 프로세스를 죽이거나 VM을 되돌리기 **전에** 증거부터 수집한다.
- 증거는 `tickets/INC-0X/evidence/`에 두고, 파일마다 수집 시각과 수집 명령을 같은 이름의 `.txt`로 남긴다.
- 실행 파일 복사본(`/proc/<PID>/exe` 등)은 실행 권한을 빼고(`chmod 000`) 압축해서 보관한다.

## 사고 신고 연습

실제 신고는 하지 않는다. 플레이북에는 "개인정보 유출 시 72시간 이내 신고" 같은 법적 기한을 적고,
테이블탑 훈련에서 그 기한 안에 누가 무엇을 하는지만 연습한다.
