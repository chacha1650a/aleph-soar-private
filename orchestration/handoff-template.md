## 입력 전 시험 카드

시나리오 시험을 인계할 때만 아래 카드·담당별 회신을 작성합니다. 작은 문서/코드 작업은 위 기본 인수 항목으로 충분합니다. workplan write 범위의 `integration/*/`는 실행별 시험 ID 디렉터리로 바꾸며 기존 증적을 덮어쓰지 않습니다.

| 항목 | 고정할 값 |
| --- | --- |

## 막힘 증거 인계

오류 사실은 즉시 알리고 해결되지 않으면 발견 후 늦어도 20분 안에 아래 내용을 묶습니다. 오차단·예상 밖 조치·비밀값 노출은 즉시 중단 대상으로 두며 20분을 기다리지 않습니다. 이 양식을 채우는 것과 실제 메시지 발송 권한은 별개입니다.

- 시험 ID·실행 버전·시각 / 마지막 성공 단계:
- 기대 결과 / 실제 응답·로그 / 필요한 도움:
- 요청 문제라면 전송 헤더·본문·Content-Type과 수신 결과 대조(비밀값/원문 개인정보 제거):
- 원래 실행 ID·요청 키·현재 대상 상태·마지막으로 확인된 단계 / 재전송 여부:

## 담당별 최종 회신 (각 1회, 입력 뒤 병렬)

- 시험 ID·출발지·관측창(KST)·버전:
- A 원본 ID/수/앱·DB 상태 / B 입력/경계·전송 / C 티켓/가동·Wazuh / D 수신/정규화/정의·n8n 중 담당 범위:
- 원문 수·고유/중복·정규화 필드 대조(해당 범위만):
- 정의 없음/비활성/미확인/정의된 규칙의 조회 0건:
- n8n 실행 ID·dry_run·실제 HTTP 노드/응답·대상 효과/원복:
- 탐지 이벤트 ID·요청 키·ticket_id·요청/응답 시각과 증적 위치:
- 차단 중 정상 사용자 / 해제·복구 결과 / 원복 후 재접근의 독립 대조:
- 티켓 수·조회 키/구간·미가동/조회 실패/가동 중 0건의 원인:
- 근거 종류·시각·링크·미확인·다음 담당/필요 입력:

오류·조건 변경은 즉시 알리고 영향받은 준비만 재확인합니다. 변화 없는 회신을 반복 요구하지 않습니다. 실제 메시지 발송은 명시 지시가 있을 때만 합니다. 최종 회신 제출과 최종 완료 판정은 별개이며 보강 후 효과·원복은 독립 검토자가 확인합니다. 보강 전 완료는 카드의 관측 완료에 한정합니다. 다른 시간창/출발지의 후속 시험은 별도 기록으로 남깁니다.

확인하지 않은 결과를 통과로 채우지 않습니다. 로컬 로그에 비밀값이 있으면 원문 대신 비밀값을 제거한 증적을 준비합니다.
