# R08 · 통신 외주 유지보수 포털과 4계층·DB 감사 증적 독립 리뷰

사용자가 통신사 외주 유지보수 업무 포털로 배경을 유지하고, 정상 업무가 있는 작은 서비스와 공격·방어 시나리오를 먼저 준비하라고 요청했습니다. 4계층 실제 연동과 DB 감사에 가산점이 있다고 가정하고 보강한 Codex 준비안을 독립 검토해 주세요. 쇼핑몰·스마트팩토리·금융·통신 후보 투표를 다시 시작하지 마세요.

AGENTS.md와 docs/21-telecom-portal-defense-plan.md를 먼저 읽으세요. 필요한 부분만 docs/12-four-layer-topic-review.md, docs/20-telecom-background-review.md, work-log/2026-10-16-codex-telecom-background-review.md, docs/API-CONTRACT.md, contracts/event.schema.json, contracts/incident.schema.json, orchestration/workplan.json에서 대조하세요. 강사 예시 원본이 없으면 저장소의 정리와 원본 열람을 구분하세요.

확정 조건은 4인, Wazuh·Graylog·pfSense·n8n·Kali Linux·Docker 사용 예정, 반 내 팀 간 공방전 예정입니다. 프로젝트 기간(2주 여부)·제품 버전·배치·장비·공방전의 웹 대상/제공 계정/허용 기법/점수·강사의 4계층 정의/필수 여부/가산점은 미확인입니다. 가정으로 평가하되 확인됐다고 쓰지 마세요. 팀 전체 합의와 사용자가 고정한 준비 방향도 구분하세요.

읽기와 공개 웹 자료 확인만 하세요. 기존 파일 수정, 설치·제품 가동·공격 시험, 커밋·푸시·PR, 메시지 발송, 다른 에이전트 실행은 요청 범위가 아닙니다. 유일한 예외로 최종 응답 전문을 새 파일 work-log/2026-10-16-claude-telecom-portal-plan-review.md에 저장해 주세요. 수신일·환경·프롬프트 경로를 첫머리에 적으세요. 같은 파일이 이미 있으면 덮어쓰지 말고 응답 본문으로 반환한 뒤 충돌을 알려 주세요. 다른 파일은 만들거나 고치지 마세요. 파일 저장 도구가 없는 환경이면 저장했다고 주장하지 말고 응답 본문을 반환하세요.

docs/21의 10절 질문 1~9에 답하세요. 특히 다음을 엄격히 검토하세요.
