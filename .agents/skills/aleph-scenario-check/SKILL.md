탐지·대응 시나리오를 구현하거나 검증할 때 사용합니다.

[시나리오 목록](../../../docs/03-scenarios.md)과 해당 변경을 확인합니다. 사용자·자산·시간창·입력 순서와 예상 결과를 적고, 정상 대조·임계 전후·다른 사용자 혼재·중복·지연 중 변경과 관련된 경우를 검증합니다.

대응을 바꿨다면 실제 테스트 대상 상태, 재시도, 실패와 원복을 확인합니다. 합성 입력의 탐지 결과, 실제 앱 상태, 외부 도구 연결 여부를 구분합니다. 실행하지 않은 조건은 미검증으로 표시합니다.

기록에는 코드·설정 버전, 입력, 관찰 결과, 증적 위치와 남은 문제를 포함합니다. `contracts/examples/`는 스키마 예시이므로 시나리오가 통과했다는 증거로 사용하지 않습니다.

입력 전 [시험 카드·회신 양식](../../../orchestration/handoff-template.md)에 시험 ID, 보강 전/후, 출발지·대상, 코드/설정 버전, 예상 입력 수, 실측/관측 구간(KST), 원본·대응 예상, 검색 주기·수집 지연의 측정/미측정/정의 없음 정책을 고정합니다. A/B/C/D가 병렬 준비 회신을 각 1회 제출하고 연결 대조가 끝나야 본 입력으로 넘어갑니다. 준비 패킷·dry_run·본 측정은 별도 실행 ID와 시간창으로 기록합니다. 미확인 회신을 준비됨으로 해석하거나 준비 패킷을 자동 재전송하지 않습니다.

실행 중인 서비스·이미지·DB·게시 워크플로가 카드의 확정 버전과 같은지 확인하고, 시험 시간대·대응 주체·주 경로를 고정합니다. 차단·복구가 겹쳐 효과 원인을 구분할 수 없는 시험은 분리합니다. 입력 전에 해제/복구 담당과 검토된 경로를 확보하고 자동화 범위(탐지·조치·효과 기록·해제)를 각각 명시합니다. 승인 후 수동 해제를 포함하는 시험을 무인 자동 해제 시험으로 바꾸지 않습니다. 이 카드나 스킬만으로 실장비 실행·배포·권한을 허가하지 않습니다.

입력 후에는 A 원본/앱·DB 상태, B 입력 수/경계·전송기, C 티켓/저장소·Wazuh, D 수신/정규화/정의·n8n을 병렬 대조하고 각자 최종 회신 1회를 남깁니다. 원본 ID·출발지·시간창으로 맞추고 다음을 각각 기록합니다.

- 원문 수신 수·고유/중복 수와 공통 필드 정규화 대조 결과는 별도입니다. 원문 도착만으로 파싱 완료를 선언하지 않습니다.
- 정의 없음은 미정의/해당 없음이고 시간값은 null입니다. 정의된 규칙을 정해진 창에서 조회한 결과 0건과 다릅니다. 미확인·실패도 0으로 채우지 않습니다.
- n8n 실행 ID, dry_run 여부, 실제 HTTP 노드 실행/응답, 대상의 실제 효과를 구분합니다. HTTP 성공만으로 차단·원복을 확정하지 않습니다.
- 저장소 미가동으로 티켓 생성 불가는 기능 검증이 아닙니다. 가동 중 조회 0건에는 조회 구간·키·대상을 적습니다.
- 측정 뒤 다른 출발지/시간창의 수동 시험을 해당 시험이나 하루 전체 0건으로 합치지 않습니다. 같은 출발지를 재사용하면 영향 이력을 대조합니다.

시험 ID·탐지 이벤트 ID·n8n 실행 ID·요청 키·ticket_id, 요청/응답 시각과 증적 위치를 실행할 때 함께 묶습니다. 실제 대상 상태 변화·차단 중 정상 사용자 동작·해제/복구 결과·원복 후 재접근을 그 시험에서 확인하고 각 단계를 미확인/실패/확인으로 남깁니다. 정상 사용자 오차단·예상 밖 조치·비밀값 노출은 즉시 중단하고, 일반 막힘의 증거 인계는 [aleph-handoff](../aleph-handoff/SKILL.md)의 최대 20분 기준을 따릅니다.

실측 중 서비스·VPN·경로·파서·대응 변경은 조율하고, 변경 시 영향받은 조건을 다시 확인합니다. 보강 후 최종 완료는 실제 효과·원복·정상 대조의 독립 확인까지 필요합니다. 보강 전 완료는 그 카드의 관측 완료이며 자동 대응 완주가 아닙니다. 근거는 직접 측정/담당 보고/코드 검사/합성 시험/실제 연결로 표시하고, 원문 민감 로그는 커밋하지 않습니다.
