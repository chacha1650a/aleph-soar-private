작업 경계와 인수 조건을 정할 때 사용합니다. 문구 수정처럼 범위가 이미 명확한 작은 작업에는 전체 계획을 다시 만들 필요가 없습니다.

프로젝트 루트의 `orchestration/workplan.json`과 해당 역할을 확인합니다. 현재 통합은 `python tools/team.py ready --track integration`, 과거 스켈레톤은 `--track legacy`로 구분합니다. `inspect TASK_ID`로 막힌 조건과 독립 진행 후보를 보고, 검증된 선행 작업 ID만 `--done`으로 전달합니다. 이 입력은 공유 작업 상태나 검증 증거를 대신하지 않습니다. 준비 후보가 나와도 brief의 미확인 조건을 실제로 확인하기 전 실측을 시작하지 않습니다.

관련 계약, 수정할 파일, 다른 담당과 연결할 지점, 결과를 관찰할 확인 방법을 task brief에 담습니다. 동시에 쓰는 파일이 있으면 한 담당으로 모으거나 작업 순서를 나눕니다. 생성된 brief는 작업을 자동 실행하지 않습니다.

공동 시험에 쓸 통합본은 관련 후보의 최신 head와 계약·처리 정책(중복·재차단·해제 등)을 함께 대조하고, 합친 최종 head에서 검증한 뒤 확정합니다. 개별 PR의 CI 통과나 로컬 통합만으로 공용 배포본 확정을 선언하지 않습니다. 병합 후 실제 배포할 커밋을 공유하고 서비스 담당이 그 버전으로 재빌드·기동을 확인합니다. 통합 중 새 커밋이 생기면 영향받는 검증을 다시 합니다. PR 번호·날짜·커밋 값은 스킬에 고정하지 않고 시험 카드/일지에 둡니다.

시험 카드에는 저장소별 커밋, 빌드 이미지 ID, DB 식별, 가져온 워크플로 JSON 해시·게시 버전을 담당 범위에 맞게 기록합니다. 소스 버전과 실행 중 버전의 일치를 확인합니다. 공동 시험은 담당·시간대를 예약하고 같은 대상/상태에 영향을 주는 시험은 한 번에 하나씩 진행합니다. 첫 연결은 주 대응 경로 하나로 범위를 고정하고, 다른 경로의 독립 준비는 병행합니다.

사람 A~D와 개발 역할은 [대응표](../../../docs/09-ai-collaboration.md)를 따릅니다. 시작 전에 시험 카드·버전·파일 소유자를 고정하고 A(포털), B(망·입력), C(Wazuh·티켓), D(수신·정의·n8n)의 준비를 동시에 모읍니다. 담당별 준비 회신 1회(준비됨/작업 필요/미확인 + 근거 + 남은 조건), 입력 후 최종 회신 1회를 기본으로 합니다. 오류·조건 변경은 즉시 알리고 영향받은 준비만 재확인합니다. 대기 중인 연결과 무관한 문서·격리 개발은 독립 진행 후보로 남깁니다.

최신 상태는 `docs/PROGRESS.md` 한 곳에 요약하며 기존 A의 편집 담당을 유지합니다. 다른 담당은 자기 일지·시험 기록에 근거를 남기고 중복 편집하지 않습니다. 일지는 상세 이력, workplan은 정적 의존성·인수 조건, 시험 기록은 실행별 증적입니다. 외부 포털 저장소는 `external_refs`로만 참조하고 로컬 read/write 경로의 저장소 경계를 풀지 않습니다.

팀 사용법은 [공통 작업공간](../../../docs/08-team-workspace.md), 조율 절차는 [AI 협업](../../../docs/09-ai-collaboration.md)을 필요한 부분만 읽습니다.
